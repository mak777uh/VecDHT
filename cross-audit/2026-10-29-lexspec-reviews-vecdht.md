И то, что список приборов берётся из каталога по префиксу, а не из списка в файле (`check-guard-selftests.py`,

пришли сегодня, когда внешний аудит показал нам, что самотест, называющий свои случаи, проверяет только их.

## V-1 (MEDIUM) — числа в шапке `verify.yml` разошлись с деревом на 40 тестов

**Что обещает файл.** Комментарий в `verify.yml` даёт точные числа с командами: `#[test]` 762, `tokio::test` 2,
всего **764**, и разбивку по крейтам: wire 57, orders 16, crypto 60, artifact 48, index 117, node 203, net 102,
embed 80, cli 79.

**Что в дереве сейчас.**

| крейт | в шапке | в дереве |
|---|---|---|
| wire | 57 | 57 |
| orders | **16** | **24** |
| crypto | 60 | 60 |
| artifact | 48 | 48 |
| index | **117** | **118** |
| node | **203** | **208** |
| net | **102** | **105** |
| embed | 80 | 80 |
| cli | **79** | **102** |
| **всего `#[test]`** | **762** | **802** (+2 tokio = 804) |

**Воспроизведение** (считает все `*.rs` под `crates/<крейт>/`, включая `tests/`):

```
$ python - <<'PY'
import pathlib, re, collections
root = pathlib.Path('crates'); per = collections.Counter(); tokio = 0
for f in root.rglob('*.rs'):
    t = f.read_text(encoding='utf-8', errors='replace')
    per[f.relative_to(root).parts[0]] += len(re.findall(r'#\[test\]', t))
    tokio += len(re.findall(r'#\[tokio::test', t))
print(dict(sorted(per.items())), 'total', sum(per.values()), 'tokio', tokio)
PY
```

**Почему это находка при вашей же дисциплине.** Комментарий с командами — сильнее комментария без них, но он
всё равно не исполняется: число в шапке CI не сверяется ни одним прибором, а `check-guard-selftests.py` проверяет
подключение приборов, не их арифметику в комментариях. Дрейф на 40 тестов никем не замечен — и это ровно тот
класс, для которого у вас есть слово «форма записи вместо механизма».

**Что предлагаю.** Либо убрать точные числа из шапки (оставив команды), либо завести прибор `check-ci-numbers.py`,
который читает числа из шапки `verify.yml` и сверяет их с деревом — по образцу вашего же
`check-ci-report-greps.py`. Второе дороже, но именно оно превращает комментарий в утверждение.

**Возможная поправка с вашей стороны:** если «cli 79» считалось без `crates/vecdht-cli/tests/`, то расхождение в
23 — вопрос определения, а не дрейфа. Тогда дефект в другом: определение счёта нигде не записано, и мой счёт
(все `*.rs` под крейтом) — единственное, что можно воспроизвести.

## V-2 (LOW) — в clone `target/` занимает место и попадает в дерево

```
$ du -sh target 2>/dev/null
```

У меня в клоне `target/` присутствует; в `.gitignore` он, вероятно, есть, но в рабочем дереве после сборки он
рядом с `lab/` и `crates/`. Это не дефект репозитория, а напоминание: ваши приборы обходят дерево (например,
`check-artifact-refs.py`), и обход, не исключающий `target/`, будет читать чужие байты. Проверять стоит именно
исключения в обходе, а не наличие каталога.
