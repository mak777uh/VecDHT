# VecDHT

**Что это.** P2P-семантический поиск и rendezvous агентов: узел публикует интент (embeddings + короткий
подписанный текст), другой узел находит его по смыслу, без обязательного центра. Ядро протокола
реализовано один раз, на Rust; языковые привязки вызывают его, а не переписывают байтовые форматы.

**Чего здесь нет.** Это не выпущенный продукт: нет релизного тега, нет опубликованного бинарника, нет
внешнего оператора этой сети и нет команды, которая поднимает узел. И нет заявления о приватности дальше
измеренного: index-node читает то, что держит.

Два документа держат этот проект отдельно от кода: спецификация
[docs/VecDHT-SPEC-v8.md](docs/VecDHT-SPEC-v8.md) — контракт и пороги (её зеркало для чтения лежит вне
git, проверка равенства — `./lab/check-spec-mirror.sh`), и [lab/](lab/README.md) — память между
сессиями: гипотезы, карточки экспериментов, архитектурные решения, синтезы, контур источников и
append-only журналы. Сколько их — порождается, а не переписывается:
[`lab/INVENTORY.md`](lab/INVENTORY.md), команда `python lab/inventory.py`. С 2026-10-25 рядом лежит
третий нормативный документ — дельта платных заказов
[docs/VecDHT-SPEC-v9.md](docs/VecDHT-SPEC-v9.md) с порождёнными ею векторами
[docs/PAID_ORDER-VECTORS.md](docs/PAID_ORDER-VECTORS.md); она зафиксирована байтово и пересчитана чужим
`hashlib` (`E-0111`), правило вывода вердикта в ней исправлено по замеру (`E-0112`, `ADR-0062`), но ни
один её объект ещё не прошёл через сеть. Порядок движения к релизу — в [ROADMAP.md](ROADMAP.md).
Каноническая версия этого текста — [README.md](README.md); при расхождении выигрывает она. README —
карта, а не источник чисел: число здесь живёт только вместе с номером замера (`E-XXXX`), командой
прогона и ссылкой на лог.

## Задача, которая здесь исчезает

Поиск агентов сегодня — централизованный справочник, то есть единая точка отказа: он умеет снять
участника с публикации, переупорядочить выдачу, притормозить конкурента и молча отдать неверный маршрут,
и никто вне этой компании не может доказать, что именно было отдано. Для витрины это приемлемо, для
открытой сети — нет, особенно когда участники — автономные программы, которые договариваются без
человека в контуре.

VecDHT заменяет эту единую точку шардовым семантическим индексом, который держат те пиры, которые в него
публикуют. Дизайн не требует, чтобы исходный издатель оставался доступен, и ни один оператор не может
ответить на запрос, на который не отвечают опубликованные записи. Записи адресованы по содержимому,
поэтому узел может показать, какие записи ему отдали, а третья сторона умеет это проверить.

## Как это работает

Издатель подписывает `Intent` и платит маленький proof-of-work. Запись назначается в один из 64 шардов
замороженным квантизатором, который приезжает как сетевой артефакт, поэтому маршрутизация — свойство
артефакта, а не живой сети. Пиры, держящие этот шард, принимают запись по явной политике приёма: квота,
сложность PoW, кап на ячейку, переживаемый список запрета и переживаемое множество отозванных ключей.
Ищущий отправляет вектор запроса, делает fan-out к провайдерам шарда через Kademlia и получает обратно
кандидатные слоты; ранжирование — дело клиента. Текст перед хешированием канонизируется в фиксированную
байтовую форму, координаты квантуются в фиксированную точку Δ=1/127 — две реализации сходятся в
идентификаторах потому, что контракт это байтовая форма, а не исполняемый код.

Читаемые байтовые форматы и пороги — [docs/VecDHT-SPEC-v8.md](docs/VecDHT-SPEC-v8.md); правила, по
которым живёт репозиторий, — [AGENTS.md](AGENTS.md); содержимое по crate'ам —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Статус: одна цифра и то, на чём она стоит

**Ориентировочная готовность v1 — около 78 %** (оценка, срез 2026-10-25; она опирается на закрытия
`E-0105` и `E-0108` и является оценкой по пяти условиям релиз-гейта, а не измерением). Покрывать
отсутствие цифры словом «готово» нельзя, поэтому она помечена как оценка.

Единица работы с 2026-10-23 — релиз-гейт (`ADR-0044`), у которого есть измеримое «готово/не готово»;
работа идёт по релизной очереди, а не по этапам P0–P7. Полная таблица пяти условий с состояниями,
история двери, отзыва и конечности кэшей и список границ — в
[`docs/STATUS-v1.md`](docs/STATUS-v1.md). Здесь остаются одна цифра готовности и четыре пункта.

* **готово** — `wire`, `crypto`, `artifact`, `index`, `node`, транспорт, эмбеддинги и CLI собираются и
  проходят тесты workspace; дверь приёма, пределы таблицы провайдеров, переживаемый запрет, переживаемое
  множество отозванных ключей и наблюдаемые имена отказа закрыты каждый своим замеренным циклом
  (`E-0087`…`E-0095`); гейт recall закрыт на ровной связной карте шардов с названной ценой (`E-0012`,
  `ADR-0004`) — recall@10 0.9645 на 50 000 и 0.9790 на 807 596 записях MS MARCO;
* **измерено один раз и на своей машине** — стенд ~200 узлов прогнан в release (`E-0105`): 192 холодных
  резолва, два официальных прогона дают p95 = 257 и 151 мс при допуске 500 мс (пять прогонов —
  257/151/189/185/117 мс). Заранее зарегистрированный фальсификатор сработал на хвосте: одна проба из 192
  не нашла провайдера за 3 с, то есть «192/192 всегда» не инвариантно к нагрузке хоста; хвост этой выборки
  пока не оформлен как гипотеза;
* **не сделано, как есть** — ни релизного тега, ни бинарника; нет двухмашинного end-to-end сценария; стенд
  не воспроизведён на хосте, которым мы не управляем; padding трафика описан в спеке и измерен как
  отсутствующий (`E-0077`); множество отзывов переживает рестарт, но производитель отзыва в продукте один:
  CLI не передаёт каталог узлов в `NetConfig.revoked_dir` (Batch C); команды, которая поднимает шардовый
  узел, нет; формальный конвейер (Verus, Kani, Lean) доказывает утверждения о моделях, а соответствие
  моделей коду исполняемым прибором не проверено;
* **счётчиков в этом файле нет** — число гипотез, карточек, ADR, синтезов, источников и журналов
  порождается в [`lab/INVENTORY.md`](lab/INVENTORY.md) командой `python lab/inventory.py`; измеренные
  величины, прогон, который их несёт, и команды съёмки — в [`docs/METRICS.md`](docs/METRICS.md).

В `main` только то, что собирается и тестируется. Закрыты гейты P2–P5 (включая транспорт и
adversarial-набор §19.3), детерминированная половина P0, гейт (v) на реальных весах и оба измеренных
гейта P0. С 2026-10-24 на каждый push в main исполняется ещё и формальный конвейер — Verus, Kani, Lean и
продуктовый срез в одной CI-работе (`.github/workflows/formal.yml`, числа и границы — `E-0099`,
`ADR-0053`); он доказывает утверждения о моделях арифметики приёма, а не о коде. Что именно не так, как в
v7.5, и что стоит в каждом crate — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md); состояние пяти условий
и границы — [`docs/STATUS-v1.md`](docs/STATUS-v1.md); формальный контур и его оговорки —
[`docs/FORMAL.md`](docs/FORMAL.md); цены и числа — [`docs/METRICS.md`](docs/METRICS.md). Что способно
сдвинуть цифру готовности — не список желаний: [ROADMAP.md](ROADMAP.md) задаёт три горизонта с выходными
критериями, которые может померить кто-то другой, и список того, чего мы сознательно не делаем.

## Быстрый старт

Команды ниже — существующая сегодня поверхность оператора (имена флагов сверены с кодом
`crates/vecdht-cli`, а не с памятью):

```
cargo build --workspace
cargo test --workspace                                       # на Windows: префикс PATH=…, см. примечание ниже
cargo run -p vecdht-cli -- artifact init --out ./artifact --dev-keys 1     # dev-артефакт, один dev-ключ подписи
cargo run -p vecdht-cli -- agent run     --artifact ./artifact --seed <32-байтный hex> --listen /ip4/0.0.0.0/udp/<port>/quic-v1
cargo run -p vecdht-cli -- agent publish --artifact ./artifact --text "<интент>" --seed <hex> --bootstrap <addr>
cargo run -p vecdht-cli -- agent find    --artifact ./artifact --text "<вопрос>" --seed <hex> --bootstrap <addr>
```

На `x86_64-pc-windows-gnu` сборке нужен настоящий C-линковщик: `blake3` компилирует нативный код, и
standalone mingw-w64 обязан стоять в `PATH` раньше любого другого gcc
(`PATH="/c/Users/Admin/mingw64/bin:$PATH" cargo test --workspace`); сборки из-под miniconda не хватает —
нет `libws2_32.a`, линкер 2.25 не тянет современный libstd, тестовые таргеты с proc-macro DLL не
линкуются вовсе. Linux и macOS не требуют ничего особенного.

**Последней команды операторской истории нет.** `agent run` — это listener, а не шардовый узел: команды
`node`, которая поднимает машину шарда с bootstrap членства и genesis, нет, и смыслового слоя входящего
трафика нет, поэтому `IntentTextRequest` не обслуживается. Публикация и поиск работают между процессами
по настоящему QUIC внутри одной машины; двухмашинного walkthrough пока нет. Это Batch C
(`docs/STATUS-v1.md`).

## Как проверить утверждение

Один канонический блок; тот же блок напечатан в [`docs/METRICS.md`](docs/METRICS.md) и в
[`lab/README.md`](lab/README.md). Дешёвые стражи из него исполнены 2026-10-25, и каждый вернул 0; пятая
строка — полный cargo-контур.

```
bash lab/check-spec-mirror.sh                                # зеркало спеки побайтово равно оригиналу (--fix обновляет)
bash lab/check-text-clean.sh --all                           # гибрид алфавитов и битая кодировка: перебором по git ls-files
python lab/inventory.py --date <YYYY-MM-DD> --write lab/INVENTORY.md   # счётчики порождаются, а не переписываются
python lab/xcheck-paid-orders.py docs/PAID_ORDER-VECTORS.md  # чужой hashlib пересобирает statement_hash по тексту документа
bash lab/workspace-verify.sh <run-id>                        # cargo test --workspace + clippy -D warnings + все приборы lab/
```

`<run-id>` — не украшение: это метка append-only блока в `lab/logs/`, и документы ссылаются на прогон по
этой метке. Прогон, на который ссылается эта страница, — `E-0113` (блок `########## E-0113 ·` в
`lab/logs/workspace-verify-2026-10-22.log`); его числа, команды, которыми они сняты, и оговорка про
неудачную попытку внутри того же блока — в [`docs/METRICS.md`](docs/METRICS.md). Формулировка «последний
полный прогон» в документы не пишется: она устаревает на каждом закрытом цикле.
`lab/workspace-verify.sh` число срезов не печатает — его вывод содержит токены выходов стадий
(`TEST_EXIT`, `CLIPPY_EXIT`, `VERIFY_FAIL`, …), а срез считается по строкам cargo `test result:`.

Правила v9 проверяются отдельно и без узла — тремя командами §V9.11, которые перечислены вместе с
циклами `E-0111`…`E-0113` в [`docs/METRICS.md`](docs/METRICS.md). Тяжёлые гейты (реальные веса, корпус
50k, бюджет памяти на 1M записей, adversarial-прогон на 600 с) по умолчанию в `cargo test` не входят — у
них бюджет по времени и внешние данные вне git; их команды перечислены там же. Если гейт не запускался в
этом окружении, это «не проверялся здесь», а не «пройден». Стражи текста и зеркал исполняются перед
каждым коммитом, а контур источников сверяется командой `python lab/library.py value --cycles 5`
(`ADR-0045`).

## Платные заказы (v9)

Следующий слой задокументирован, измерен как байты и не развёрнут: агент публикует задачу со ссылкой на
эскроу и дедлайном, другой агент сдаёт набор артефактов, узел проверяет его в конечном бюджете, а
подписанная квитанция (вердикт, список аксиом, тайминги, дайджест образа) решает выплату. Главное правило:
квитанция проверяема без судьи — вердикт обязан выводиться из полей самой квитанции любым держателем
заказа.

Байтовые правила и машина состояний — [docs/VecDHT-SPEC-v9.md](docs/VecDHT-SPEC-v9.md); векторы, которые
обязан повторить клиент, — [docs/PAID_ORDER-VECTORS.md](docs/PAID_ORDER-VECTORS.md); проектное
повествование и разбор правила — [docs/PAID_ORDERS.md](docs/PAID_ORDERS.md) и
[docs/VecDHT-v9-REVIEW.md](docs/VecDHT-v9-REVIEW.md). Векторы перепроверены независимым `hashlib`
(`E-0111`), само правило вердикта исправлено по замеру (`E-0112`, `ADR-0062`), а клиент, написанный только
по этим двум документам и не читавший `crates/`, воспроизводит те же байты; до зелёного прогона он нашёл
семь дефектов — шесть в тексте правил и один в самом проверяющем приборе (`E-0113`, строка `result:`
карточки). При этом осталось: узел заказов не принимает, `vecdht-orders` не входит в граф зависимостей
узла, и нет образа верификатора, эскроу-контракта и тестнета.

## Лаборатория

Архитектурные изменения идут через научный контур — и это единственный способ поменять семантику
протокола: гипотеза (`H-XXXX`) → карточка эксперимента с порогом, зафиксированным **до** пре-регистрации
(`E-XXXX`) → решение (`ADR-XXXX`), одно решение на ADR. Порог нельзя придумывать после того, как увидел
результат; изменённый порог — это новый эксперимент. Отрицательный результат остаётся в `lab/` с вердиктом
`refutes`: журналы append-only. Сколько в `lab/` чего лежит — [`lab/INVENTORY.md`](lab/INVENTORY.md),
порождённый командой `python lab/inventory.py`; в этом абзаце счётчиков нет.

Что делает контур пригодным для агента с обнулённым контекстом:

* **PRE_FIX-снимок** — оракул исполняется на дереве до правки, и его вывод коммитится: предсказание цикла
  проверяется числом, а не памятью;
* **n=2** — вектор фактов обязан совпасть между двумя прогонами на неизменном дереве; факт годен в вердикт
  только если он инвариантен к расписанию шагов (правило 7 (е)); проверяемость строки = отношение запаса до
  границы к межпрогонному разбросу, и ниже ~10 односторонний абсолютный порог не является вердиктом
  (правило 7 (д));
* **ресурсы** — RAM и свободный диск меряются до сборки, после каждого прогона и в итоге лога, а полный
  cargo-контур (`bash lab/workspace-verify.sh <run-id>`) входит в закрытие цикла;
* **круг «боль → источники → рубрика Lean → оракул»** (`ADR-0045`, `ADR-0048`) — перед пре-регистрацией
  цикл обязан пройти шаг 0: сформулировать боль, найти, как её решали другие
  (`python lab/sources.py hunt "<боль>" --github --paths src/banman.cpp` печатает черновики строк индекса
  со ссылками и pinned sha), записать их в `lab/library/index.jsonl` и ответить на четыре вопроса рубрики
  Lean в карточке. Механическая проверка — `python lab/cycle-gate.py H-XXXX` (ненулевой выход = круг не
  оформлен; сам гейт проверяется `python lab/cycle-gate.py selftest`). Классы источников — «бумага»,
  «спека», «реализация» (чужой код с пином на sha и путём внутри репозитория);
  `python lab/library.py verify` сверяет arXiv-id с названием, а ссылку на код — с тем, что этот файл
  действительно есть в этом коммите; `python lab/library.py value --cycles 5` следит, чтобы окно сверки не
  превратилось в декорацию;
* **формальная модель рядом с решением** — Lean применяется точечно и по рубрике (`lab/lean-rubric.md`):
  рецензия семантики решения, математическая разведка гипотезы до оракула и полный перебор конечного
  дискретного пространства кандидатов (`native_decide`). Время, байты, пакеты, настоящая криптография и
  сеть — только оракул. Оговорка остаётся: `native_decide` доверяется как **аксиома**, ядро Lean результат
  не перепроверяет, и это видно только `#print axioms` по терминам доказательств, а не `grep` по
  исходнику. С 2026-10-24 это не ручная оговорка, а печатаемое число приборов (`bash lab/lean-check.sh`,
  `python lab/lean-check.py selftest`); сами числа и границы формального контура —
  [`docs/FORMAL.md`](docs/FORMAL.md);
* **спека правится только по замеренным фактам** и только отдельным коммитом; внутри замерного цикла
  `docs/` не трогается (`ADR-0042`, слово владельца 2026-10-23);
* **числа, порождаемые из дерева, принадлежат генератору, а не прозе**: счётчики —
  [`lab/INVENTORY.md`](lab/INVENTORY.md), измерения — [`docs/METRICS.md`](docs/METRICS.md), README —
  только id и указатели.

Первые циклы (геометрия шардов): `E-0001`…`E-0015`, решения `ADR-0001`…`ADR-0004`. Дальше — транспорт и
приватность (§9–§13), Lean-модель дверей (`E-0078`, `S-0004`), цена строк спеки (`E-0081`…`E-0084`,
`S-0005`), дверь и кэши (`E-0085`…`E-0095`), платные заказы (`E-0111`…`E-0113`). Полный список —
`lab/experiments/`; контракт для агентов — `AGENTS.md`, протокол лабораторной работы — `lab/README.md`.
