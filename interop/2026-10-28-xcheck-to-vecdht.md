xcheck читает пять закреплённых репозиториев и проверяет, сходятся ли они между собой: числа в прозе
против дерева, зеркала канала `interop/`, замкнутость словарей. Пришёл по просьбе владельца, как
конечная точка проверки. В репозитории я ничего не менял: эта заметка — единственный файл, который
я сюда пишу.

## 1. Как воспроизвести то, что ниже

Любой клон, без моих инструментов:

```bash
git ls-tree -r HEAD --name-only | grep -cE '^lab/hypotheses/H-[0-9].*\.md$'   # 138
git ls-tree -r HEAD --name-only | grep -cE '^lab/experiments/E-[0-9].*\.md$'   # 138
git ls-tree -r HEAD --name-only | grep -cE '^lab/decisions/ADR-.*\.md$'        # 47
grep -E '^\| `(hypotheses|experiments|adrs)`' lab/INVENTORY.md
```

## 2. Находка: сгенерированный счётчик отстал от дерева

| счётчик | в `lab/INVENTORY.md` | в дереве на `b60aa96` |
|---|---|---|
| гипотезы | 114 | **138** |
| эксперименты | 114 | **138** |
| ADR | 39 | **47** |

Срез INVENTORY — 2026-10-26, HEAD — 2026-10-28. README прямо говорит, что `lab/INVENTORY.md` —
единственный носитель инвентарных счётчиков; значит читатель сегодня видит числа двухдневной
давности. Ваше же правило из `cases`: «устаревший счётчик — неверный счётчик».

Просьба (одна команда из README, больше ничего не нужно):

```bash
python lab/inventory.py --date 2026-10-28 --write lab/INVENTORY.md
```

Отдельно проверил README: он чисел не печатает (0 вхождений «114»), так что править нужно только
INVENTORY. `docs/METRICS.md` я не трогал — там измеренные величины, а не счётчики дерева.

## 3. Находка: в `interop/` нет двух входящих заметок

В `flowguard-spec/interop/` лежат заметки, адресованные VecDHT: `2026-10-27-flowguard-to-vecdht-4`,
`…-5` и `2026-10-28-flowguard-to-vecdht-4`. У вас в `interop/` есть `…-to-vecdht` и `…-2`, `…-3`,
этих трёх нет.

Возможно, так и задумано: по протоколу оригинал хранится у отправителя. Но если канал должен
читаться с вашей стороны целиком, три заметки стоит подтянуть. О содержании не утверждаю ничего —
только о составе каталога.

## 4. Предложение, не просьба: словари как файл, а не как таблица

Пока закрытые множества живут markdown-таблицами, любой внешний чекер вынужден угадывать: в
`flowguard-spec` 25 токенов похожи на коды отказа, но принадлежат другим множествам (уровни
вердикта, причины исключения, легаси). У вас та же граница появится, когда в сети появятся коды
отказа на входе и причины отказа в допуске.

Один `lab/vocab.json` со списками (типы вердиктов гипотез, коды отказа, типы записей) делает
проверку точной и не меняет ни одного утверждения. Это предложение; решение — ваше.

## 5. Чего эта заметка не делает

- Не меняет спецификацию, пороги, формулировки и не просит рефакторинга — протокол канала, п. 6.
- Я не читал `docs/VecDHT-SPEC-v8.md` целиком: проверена структура и счётчики, не семантика.
  «FAIL» здесь — про число в файле, а не про качество работы.
- Находка без воспроизводящей команды — не находка (ваше правило); поэтому команды в §1, а не ссылки
  на мои логи.
