# Релиз-карта v1: гейт §18 → чем закрыт → что осталось

Документ отвечает на один вопрос: **почему ещё нельзя поставить релизный тег**. Он не обещание и не
спека — спека живёт в `docs/VecDHT-SPEC-v8.md`, статус — в `docs/STATUS-v1.md`, очередь — в
`docs/PLAN-v1.md`. Здесь только карта: каждая строка обязана назвать исполняемый прибор или id
замера, иначе строка помечена словом «не проверено».

Составлены три факта, и только три: что говорит §18, что реально лежит в `crates/` и `lab/`, чем это
подтверждено. Слово «закрыт» здесь значит «есть карточка с вердиктом и прибор, который исполняется в
CI», а не «время вышло».

## §18.1 — P0, измерения

| Гейт | Чем закрыт | Состояние | Что нужно, чтобы закрыть остаток |
|---|---|---|---|
| (i) throughput эмбеддинга | `crates/vecdht-embed/tests/p0_harness.rs`, `E-0003` | измерен: 10,96–11,96 emb/s на поток, 17,82–18,09 на четырёх, насыщение после 4 | нечего: у гейта нет pass/fail, «закрыт» = бюджеты пересчитаны |
| (ii) ANN recall@10 ≥ 0,95 | `crates/vecdht-embed/tests/p0_real_corpus.rs`, `E-0004`, `E-0006`, `E-0012`, `ADR-0004` | закрыт по числу: 0,9645 (50k) и 0,9790 (807 596) при fan-out 16,0/16 на ровной связной карте | цена названа (25 % корпуса на запрос, ×16 работы на узел); граница пригодности ~100M в §8.5.1 |
| (iii) прирост реранка ΔnDCG@10 ≥ +8 % | контракт сортировки в том же харнесе | не измерен: требуемый кросс-энкодер в дереве не реализован | реранк остаётся opt-in и не входит в ядро обещаний качества |
| (iv) детерминизм 1000/1000 | `crates/vecdht-embed/tests/p0_harness.rs` | зелёный на потоках {1,2,4,8,16}; сравнение AVX-512 / AVX2 / NEON не выполнено | три машины: на одном хосте проверяется только потоковая половина |
| (v) candle modernbert, косинус ≥ 0,999 | `E-0002`, `ADR-0002` | 5/5, косинус 1,000000 | нечего |

Полнота под фильтром §12.7 измерена отдельно от строки (ii) и строку не заменяет: `E-0146`,
`lab/logs/e0146-all.log`. Фильтр не стоит ни одного хита внутри списка зондирования
(`RECALL == COVERAGE` во всех 12 клетках четырёх плотностей × трёх размеров списка), и вся потеря
при разреженном классе — цена зондирования: при 2 % платных четыре кластера из шестнадцати дают
906 ‰ идеального ответа, один — 237 ‰; при 1 % — 520 ‰ и 131 ‰. Это снимок синтетического корпуса,
а не обещание: обещать полноту под фильтром без адаптивного `nprobe` нельзя (`OPEN-QUESTIONS`
п. 86), а машиночитаемой проверки «узел применил предикат» у просителя нет — `MatchResult` не несёт
атрибутов.

## §18.7 — P6, SDK / relay / метрики

Ни один пункт гейта не закрыт как сеть между двумя машинами. Что сделано вместо него — тонкий слой
команды, а не замер: `vecdht-cli` поднимает узел из файлов церемонии (`E-0118`, `E-0119`), загружает
центроиды (`E-0121`), подписывает и рассылает отзыв (`E-0120`), переживает рестарт (`E-0124`),
считает аптайм от старта (`E-0130`), а приватность диска проверяется прибором
`crates/vecdht-cli/tests/s13_disk_privacy.rs` (`E-0108`). Нижняя половина relay-пункта теперь есть
в дереве и проверена: `Role::Relay` поднимает сервер circuit relay v2, цель без прямых
listen-адресов достижима по `/p2p/<relay>/p2p-circuit/p2p/<target>`, прикладной handshake VecDHT
проходит в обе стороны (`E-0145`, два теста на настоящем QUIC, `WIRE_TOUCHED=0`). Это loopback:
WAN-числа не мерились. Остаток гейта: find p50 ≤ 1,5 с и p95 ≤ 4 с через WAN, relay-путь равный
прямому, метрики по сегментам, replica lag, `applied_seq`.
Состояние: **механизм релея есть; сеть между двумя машинами — не проверено в v1**.

## §18.8 — P7, hardening

Adversarial-набор §19.3 — прибор есть (`crates/vecdht-node/tests/adversarial.rs`). Аудит «на диске нет
ни текста, ни f32» — исполняемый тест, а не пункт чек-листа. Retry/timeout-политика и observability —
в статусе «нет метрик-эндпоинта» (`docs/STATUS-v1.md`). Финальная сверка README со спекой стражем
`lab/check-claim-map.py` — закрыт (`E-0123`).

## Итог: почему тега ещё нет

Четыре причины, и все четыре наблюдаемы:

1. Одна незакрытая строка гейта P0 — (iii) прирост реранка: требуемого кросс-энкодера нет, поэтому
   реранк не может входить в обещания качества, и либо он делается, либо спека это фиксирует словами
   «opt-in».
2. Ни один сетевой гейт не мерился между двумя машинами: §18.2 (TTL и relay), §18.3 (golden на чужом
   хосте), §18.7 (WAN целиком). Прибор для второго пункта существует (`lab/two-hosts.sh`), не
   существует вторая машина.
3. Релизный тег и GitHub Release — действие владельца по правилам красной зоны; сам релизный
   комплект уже прибор (`lab/check-release-kit.sh`, `E-0126`).
4. Измеренная и не залатанная дыра в отзыве: при отказе записи `revocation.bin` узел забывает nonce
   из памяти и продолжает обслуживать, то есть рестарт амнистирует отозванный сертификат
   (`E-0136`, вердикт `refutes`, `lab/logs/e0136-all.log`). Это не риск «где-то в будущем»: ветка
   достижима обычной ошибкой диска. Выбор политики (`OPEN-QUESTIONS` п. 73) — красная зона, и
   формулировка `ADR-0050` («отзыв не снимается ничем») обязана получить оговорку или починку кода
   до тега.

Готовность по пяти условиям v1 — ~85 % (оценка над условиями, не измерение; обоснование сдвигов —
в `docs/STATUS-v1.md`). Числа этой карты не замораживаются: они украдены у закрытых карточек, и при
расхождении верна карточка, а не строка таблицы.

## Чего этот документ НЕ делает

Не правит ни одного порога, ни одной формулировки спеки, ни одного вердикта; не является зеркалом
`docs/VecDHT-SPEC-v8.md` и не проверяется стражем зеркала. Не обещает срок: строка «не проверено» —
это состояние, а не план. Не вводит новых дескрипторов: каждая ссылка ведёт на карточку, ADR или
файл прибора, который уже лежит в дереве.
