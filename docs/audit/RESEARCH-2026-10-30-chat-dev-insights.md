# Инсайты для разработки из чата «ресечим/делаем (c) AI» — 2026-10-30

Разбор экспорта (7 022 сообщения, 2024-10-16 → 2026-10-30) **с точки зрения разработки**, а не
дистрибуции. В чате 3 909 уникальных ссылок: arxiv 1 906, github 886, huggingface 241. Тематически
к нашим предметам относятся 685 сообщений; ядро чата — RL/LLM-обучение, к VecDHT это отношения не
имеет.

Честно: **полезного для кода мало**. Из 685 тематических сообщений к нашей разработке применимы
пять находок, и только одна из них меняет план. Ниже они с оценкой применимости.

## F1. Ниша «доказательства для агентов» уже занята несколькими продуктами — **высокая применимость**

Цепочка: в чате обсуждали «прошивку для агентов» с гейтами и evidence. Поиск по этому следу вывел
на целое семейство:

- **Agnys Agent Evidence Benchmark v0.1** (agnys.net, 27.07.2026) — публичная методика оценки
  «записей агента»: 5 измерений × 5 сценариев = 25 проверок, шкала 0–2;
- `aegisproof` — vendor-neutral evidence packages с SHA-256 для AI-систем, проверка в CI;
- `agentwitness` — verifiable evidence for AI-assisted engineering;
- `agent-evidence-gate` — детерминированный «гейт доказательств доставки»;
- `AgentGate` — коммерческий compliance-API с «8 quality gates, SHA-256 evidence chains»;
- **HOL Guard** (301,76 в PoU) — «security receipts» для агентов.

**Что это значит:** спрос на слой «докажи, что агент сделал именно это» подтверждён рынком — и мы не
первые. Наши v9-квитанции конкурируют не с пустотой, а с пятью продуктами, у которых уже есть
методика, бенчмарк и CI-проверка.

**Чем мы отличаемся (и это надо удержать в разработке):** у них — централизованный сервис/библиотека,
у нас — content-addressed записи в P2P-индексе, где квитанцию можно проверить, не обращаясь к сервису.
Если v9-квитанция требует нашего узла, чтобы её прочитать, мы просто хуже этих пяти.

**Действие:** прогнать наши v9-квитанции по пяти измерениям Agnys (ниже) и записать, что мы не
покрываем. Это дешёвый внешний аудит спеки.

## F2. Пять измерений, которыми меряют «доказательство» — **высокая применимость**

Agnys публикует методику **до** результатов, и это само по себе приём, который стоит скопировать.
Измерения и сценарии:

| измерение | вопрос | что в нашей v9-квитанции |
|---|---|---|
| **capture coverage** | есть ли запрос, активность, выбор инструмента, аргументы, ответ/ошибка, побочный эффект | частично: verdict, axiom list, timings, image digest |
| **attribution** | агент/модель, сессия, пользователь, целевая система, время — различимы | `owner`, `epoch`, `seq` — но нет привязки к человеку/сервису |
| **oversight linkage** | привязано ли одобрение к **точному** действию, можно ли сравнить исполненное с одобренным | не описано — вероятный пробел |
| **integrity** | видно ли изменение/удаление/переупорядочивание после записи | подпись и дайджест есть; якоря (anchor) нет |
| **reconstruction** | может ли посторонний пройти по записи хронологически и экспортировать | зависит от клиента; не специфицировано |

**Действие:** добавить в `docs/PAID_ORDERS.md` раздел «что квитанция обязана содержать» — по этим
пяти измерениям, с явным «не покрыто» там, где не покрыто. Это не копирование чужой методики, а
внешний чек-лист, который можно цитировать.

## F3. MCP стал де-факто центральным каталогом — **средняя применимость**

В чате: `awesome-mcp-servers`, `mcp-agent`, `agentgateway` («agentic proxy for AI agents and MCP
servers»). То есть экосистема агентов уже собралась вокруг **списка серверов** — ровно тот
центральный каталог, против которого мы выступаем.

**Действие (два):**
1. В «почему не централизованный маркетплейс» сослаться не на гипотезу, а на живой пример: реестр
   MCP-серверов и прокси к ним.
2. Для тестового корпуса взять **карточки MCP-серверов** как реальные записи для индексации: это
   готовый датасет с настоящими описаниями, а не синтетика.

## F4. Multi-step retrieval с контролем покрытия — **низкая-средняя применимость**

Из чата: `T-Search` (t-tech, HF) — агентная модель поиска с multi-step, контролем покрытия вопроса
и сохранением полезных evidence-chunks между итерациями; обсуждение предлагало прикрутить как
отдельный слой и сравнить A/B.

Для нас это **не слой сети**, а стратегия клиента: наш finder возвращает кандидатов, клиент решает,
идти ли вглубь. Полезно как описание того, чего ждёт потребитель, и как кандидат в reference-client
после v1. В ядро не берём: 35B-модель в узле — не наш масштаб.

## F5. Операционные уроки локального инференса — **низкая, но конкретная**

Из обсуждений (Victor, Misha, banzay): падение скорости до 2× при заполнении контекста под 100 %
(49 → 25 tok/s), необходимость headroom по GPU, headless-инференс на отдельной карте, иначе
watchdog убивает процесс и роняет GUI.

**Действие:** в требованиях к оператору (документ, который просят гранты и пилоты) назвать
минимальную конфигурацию для узла с эмбеддингами: отдельный GPU-инстанс или запас по памяти,
без совместного использования с десктопом. Это одна строка, но она снимает половину вопросов
«почему у меня медленно».

## F6. Что из чата **не** берём

- VSA/гипермерные векторы (arxiv 2501.05368): интересно теоретически, но наш канон фиксирован
  (Δ = 1/127, 64 шарда), менять его ради формализации — нарушение правила «спека меняется только на
  измеренном факте».
- RAG-статьи (GraphRAG, HybridRAG, Astute RAG и т.п.): наш слой — не RAG, а дискавери; клиент
  строит RAG поверх. Полезно для раздела «кто наши пользователи», не для кода.
- Lean/теоремы (31 сообщение): к VecDHT не относится, к flowguard/lexspec — возможно, но там свой
  контур.

## Что делать в разработке (3 действия по цене)

1. **Чек-лист квитанции по пяти измерениям** (F2) — полдня, снимает главный вопрос «чем вы
   отличаетесь от Agnys/HOL Guard».
2. **Тестовый корпус из карточек MCP-серверов** (F3) — день, даёт реальные данные вместо синтетики
   и одновременно аргумент для «почему».
3. **Строка про операторское железо** (F5) — час, нужна для пилотов и грантов.

## Границы

- Это разбор ссылок и обсуждений, а не проверка продуктов: ни Agnys, ни HOL Guard, ни T-Search я не
  запускал.
- «Пять продуктов в нише» — результат одного поиска по следу из чата, не систематический обзор
  рынка; список может быть неполным.
- Применимость оценена мной; ни одна находка не меняет протокол — менять его можно только через
