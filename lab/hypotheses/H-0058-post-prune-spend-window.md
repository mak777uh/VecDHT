# H-0058 — окно расхода post-prune приёма синхронизировано с prune издателя: `Expired` цели и дыра таблицы истекают одним бакетом

## Наблюдение

`E-0047` измерил окно `Spend::consume` для приёма бакета 0: граница `issued + buckets(ttl)`
включительно `Ok`, +1 — `Expired`. `E-0057` показал, что после prune выдача возвращается
НОВЫМИ строками нового бакета. Не мерилось: живёт ли post-prune приём (бакет 20) ровно до
бакета 39 в расхода и истекает ли на 40 — то есть совпадает ли отказ ЦЕЛИ с дырой ИЗДАТЕЛЯ.
Из кода обе границы выведены из одной величины `buckets(ttl_sec) = 19`:
`Issuer::prune` убирает строку при `bucket < now − 19` (для 20 это `now ≥ 40`),
`Spend::consume` даёт `Expired` при `now > issued + 19` (для 20 это `now ≥ 40`). Тогда
память расхода издателя не может пережить окно приёма цели, и наоборот — инвариант §12.3
без измеренного подтверждения.

## Гипотеза (операационализируемое ядро)

Приём A20 (выписан бакетом 20 после prune таблицы из 100 000 строк бакета 0, `ttl_sec=300`):

| Шаг | Утверждение (порог) |
|---|---|
| (1) `consume` A20 при now=39 | `Ok`, `Grant.seeker == A`, `Grant.issued_bucket == 20` |
| (2) повтор A20 при now=39 | `AlreadySpent` (память расхода держит бакет 40) |
| (3) A20 при now=40 | `Expired` — ровно тот бакет, в котором prune выбрасывает строку 20 |
| (4) побратим B20 (тот же слот/цель, другой seeker) при now=39 | `Ok` независимо от расхода A; при now=40 — `Expired` |
| (5) живой `Find` A при now=40 | 3 НОВЫХ строки бакета 40 (байты ≠ A20), `live == 3` — Issue-путь синхронно выбросил строки 20 обоих seekers |

Порог (3)+(5) вместе — различающий: если бы цель принимала кадр на 40, когда издатель
уже выбросил строку (или наоборот) — инвариант синхронности сломан.

## Фальсификаторы

(а) повтор предъявления обслужен; (б) цель приняла/отвергла приём вне синхронной грани
(now=39 не Ok или now=40 не Expired); (в) расход A заблокировал побратима B или grant B
выдан на чужого seeker'а; (г) пустой prune не вернул дыру / строки 20 пережили собственный
prune / live разошёлся с 3; (д) находки или выдачи пропали на подготовительных шагах;
(е) `accept.ttl_sec != 300` или `buckets(300) != 19` — чужая арифметика; (ж) побратим B не
на тот же слот; (з) grant не связан с A20.

## Скоуп и границы замера

Одиночный primary, `Spend::new(300)` на стороне тестовой цели (`identity(77)` — владелица
одной из записей); prune-сторона — живой `Find`-путь. Побратим B20 — отдельный seeker при
том же `(target, slot)`. Окно памяти расхода (`expires = issued + ttl + 1`) из кода не
меряется напрямую — следствия (2) на now=39 и (3) на now=40 его опосредованно подтверждают.
