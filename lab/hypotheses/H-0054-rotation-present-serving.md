# H-0054 — путь обслуживания `ADR-0013` переживает ротацию эпохи: довоенный приём остаётся одноразовым, живёт по подписи издателя, а отсутствие прежнего издателя в списке маскирует ошибку

status: proposed
kind: measurement
claim: "`E-0050` померил живучесть приёма на смене эпизоды «голым» `Spend::consume`,
`E-0051` померил `session::serve_request` внутри одной эпохи. Строка §12.3 «…ранее выданные
доживают TTL у целей, потому что проверяются по подписи издателя, а не по его текущей
таблице» через живой вход цели (`serve_request`) на ротации не мерилась ни разу, как не
мерилось и поведение списка издателей, из которого прежний издатель уже выпал. Утверждение:
после килла primary и живых выборов (эпоха +1) — (1) довоенное предъявление (`present` =
кадр F0), обслуженный до ротации, при повторе через новый `query_id` даёт ровно
`TextError::Spend(AcceptError::AlreadySpent)`, а не `Expired` и не `Ok`; (2) СВЕЖАЯ запись
расхода (эмуляция рестарта цели) после ротации обслуживает тот же довоенный кадр и в
`Grant.issuer` возвращает адрес мёртвого издателя; (3) тот же кадр при списке выживших без
прежнего издателя даёт `NotSignedByShardHolder` — то есть маска «подписан не держателем»
покрывает и «издатель выпал из ростера», и это поведение детерминировано порядком цикла в
`serve_request`; (4) кадр нового primary, предъявленный по списку выживших, обслуживается с
`Grant.issuer == новый издатель`, байты кадра разошлись с F0."
falsifiable: "(а) корректное довоенное предъявление до ротации не обслуживается; (б) повтор
после ротации обслужен `Ok` (одноразовость пути зависит от эпохи) или упал в `Expired`
(вне зависимости от бакета); (в) свежая запись расхода после ротации отказала довоенным
кадрам (приём умер вместе с издателем вопреки §12.3); (г) кадр мёртвого издателя при
списке без него обслужен `Ok` (список держателей ни на что не влияет); (д) кадр нового
издателя не обслуживается по списку выживших или `MatchResult` пропал; (е) за 30 шагов
выборов новый primary не выбран (харнес сломан, не гипотеза)."
thresholds: "Зафиксированы до прогона (этот файл + оракул в том же коммите): (1)
`serve_request(req(F0), issuers_all, b0)` → `Ok`, `grant = (seeker, SHARD, slot0, old_me)`,
повтор тем же запросом → `Err(Spend(AlreadySpent))`; (2) `serve_request(req(F0,
query_id=302), issuers_all, b1)` → `Err(Spend(AlreadySpent))`; (3) `serve_request` тем же
кадром со СВЕЖИМ `Spend::new(300)` при бакете `b1` → `Ok`, `grant.issuer == old_me`;
(4) `serve_request(req(F0), issuers_new = выжившие без old_me, b1, свежий Spend)` →
`Err(NotSignedByShardHolder)`; (5) `accepts(find@new)` = 1 кадр, байтово ≠ F0,
`serve_request(req(F1), issuers_new, b1)` → `Ok`, `grant = (new_me, seeker, SHARD)`;
в `eprintln` — `live` новой таблицы. Фальсификаторы (а)…(е) — встроенные assert'ы
оракула `tests/rotation_present_serving.rs`. Пороги не меняются задним числом; дефект
формулировки — append-ДИАГНОЗ в лог до зачётного прогона."
