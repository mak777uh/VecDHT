# H-0045 — «одноразовость расхода проверяет цель» §12.3 — пятая спека-фикция: `Spend::consume`
# не вызывается ни одним живым путём; `IntentTextRequest` физически не несёт приёма,
# предъявлять нечего

## Гипотеза

§12.3 (репо, строка 1270): «цель сверяет подпись кадра с публичным ключом издателя …
и проверяет … одноразовость расхода». §18.6 гейт P5 повторяет: «rendezvous-приём
проверяется целью и одноразовый». Проверяемое ядро — стыкуется ли это обещание с кодом:

- `rendezvous::Spend` существует и корректен как библиотека (unit-тесты `consume`,
  `AlreadySpent`, граница `now == issued + ttl` включительно) — это уже измерено и
  спорно не будет;
- **в продуктового пути нет ни одного вызова**: `grep "Spend" node.rs` — ноль (проверено
  при разведке: `Spend` в `src/` только в `rendezvous.rs` и ре-экспорте `lib.rs:55`);
  `ShardNode` не содержит поля расхода;
- **предъявить приём не чем**: `IntentTextRequest { query_id, target_ed25519, slot }`
  (`vecdht-wire/messages.rs`) не имеет поля для приёма/кадра приёма; сторона цели в
  `session.rs` (`parse_request` → `sign_response`) проверяет только адресата, вид кадра,
  подпись ответа и UTF-8 — отсечь запрос без приёма она не может, потому что запрос его
  не несёт по формату;
- `check_accept_policy` в `vecdht-net/agent.rs` — проверка **seeker'ом** приёма,
  выданного index-node (адресат/ttl/истечение перед предъявлением), а не расход целью;
  она не трогает `Spend` и не делает цель подотчётной.

Формулировка гипотезы: в v1 «одноразовость расхода» — API встраивателя (как denylist в
`E-0042`/`ADR-0009`): тип `Spend` экспортирован, вызывается только тестами, живой узел
или библиотека сессии его не зовёт, и протокольного кадра предъявления в v8 нет —
гейт §18.6 «приём проверяется целью и одноразовый» невыполним штатным путём.

## Фальсификатор

Достаточно одного:

- **(а)** любой hit `Spend`/`consume` в продуктовом `src/` вне `rendezvous.rs`/`lib.rs`
  (инвентарь) — тогда путь вызова существует, фикции нет;
- **(б)** в `IntentTextRequest` или другом кадре найдётся поле приёма/grant — тогда
  предъявление протокольно возможно;
- **(в)** поведение «запрос без приёма» отклоняется на стороне цели (ораклу-тесту
  `session::parse_request` вернёт `Err` на корректно адресованном запросе) — тогда
  хотя бы проверка наличия предъявления где-то есть;
- **(г)** `check_accept_policy` вызывает `Spend`/мутит расход — тогда цель-подобная
  подотчётность всё-таки вшита в seeker-путь (частично).

## Оракул

Инвентарь (в `lab/e0045-run.sh`, до поведенческого блока):

1. `grep -n "Spend\|\.consume(" crates/vecdht-node/src/node.rs crates/vecdht-node/src/session.rs crates/vecdht-net/src/agent.rs` — перечень всех hits с классификацией (документирующий комментарий `agent.rs:267` «та же граница, что у `Spend::consume` в узле» — не вызов);
2. `grep -n "struct IntentTextRequest" -A 8 crates/vecdht-wire/src/messages.rs` — состав полей;
3. `grep -rn "Spend" crates --include=*.rs -l` — замкнутость на `rendezvous.rs`/`lib.rs`/тесты.

Поведенческий оракул `crates/vecdht-node/tests/accept_presentation_api_only.rs`:
корректно адресованный `IntentTextRequest` (encode_request с `query_id`, свой `slot`)
проходит `session::parse_request(me)` → `Ok` без всякого приёма (фальсификатор (в)),
`sign_response` владельца отвечает текстом (ответ существует без предъявления),
`verify_response` seeker'а принимает ответ; отдельно `Spend::new` + два `consume` одного
кадра → второй `AlreadySpent` (тип работает, но только как библиотека).

## Порог (фиксируется до прогона)

(1) инвентарь node.rs/session.rs: ноль вызовов `Spend`/`consume` в продуктовом коде
(единственный hit — комментарии/экспорт, перечислить байтово); (2) поля
`IntentTextRequest` — ровно `query_id/target_ed25519/slot`, приёма нет; (3) оракул:
`parse_request` на запросе без приёма даёт `Ok`, цикл sign/verify проходит;
(4) `Spend::consume` того же кадра дважды: `Ok`, затем `Err(AlreadySpent)` — библиотека
исправна. Провал (1)/(2) = (а)/(б), провал (3) = (в), провал (4) = сломанный оракул.

## Входы и окружение

Дерево после закрытия `E-0044` (заголовок: HEAD содержать коммит закрытия), debug,
`-j 2`, `RAYON_NUM_THREADS=2`, mingw64 в PATH с запуска (уроки `E-0042`/`E-0043`).
Единицы helper'ов сверены по сигнатурам до пре-регистрации (урок `E-0044`):
`testing::clock(bucket)` принимает бакет. Ожидаемое следствие при подтверждении —
правка §12.3 («цель проверяет» → «одноразовость — API встраивателя; кадра предъявления
в v8 нет») и строки гейта §18.6 + ADR-0011 + зеркало, как `ADR-0009` для denylist.
Правка спеки не предвосхищается: порог (1)…(2) меряется фактом, не интерпретацией.
