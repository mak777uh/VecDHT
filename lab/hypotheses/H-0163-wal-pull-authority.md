# H-0163 — Хвост WAL принимается только от подписанного primary принятой эпохи

## Боль

Аудит 4-го круга (D1) назвал дверь `handle_pull_response`: ответ `WalPullResponse` собирается
неподписанным, эпоха берётся из неподписанного тела и подставляется в каждый `ReplicateOp`, а
`seq` — из фреймов. `apply_replicated` проверяет только нижнюю границу эпохи, поэтому ответ с
большей эпохой и произвольными `seq` двигает `applied_seq`, слоты и выдачу реплики. Комментарий
`messages.rs` («фреймы отдаются как есть, каждый уже подписан») относится к `ReplicateOp` в
доставке, а не к durable-фрейму WAL: подписи в нём нет по формату `wal.rs`.

Владелец делегировал красную зону словами «просто сами делайте как оптимально, спека не закон,
можно её дорабатывать»; приняты рекомендации Q1 (вариант B) и Q2. `owner == from` для `Publish`
этой карточкой не трогается (T1 — отдельная).

## Что проверяется

1. `crates/vecdht-wire/src/frame.rs`: `Kind::WalPullResponse` переезжает в `signature_required` —
   дверь `on_frame` отбрасывает неподписанный кадр до обработчика.
2. `crates/vecdht-node/src/node.rs`, `handle_pull_request`: ответ подписывается
   `self.id.sign_body(domain::WAL, Kind::WalPullResponse, &resp.body_bytes())` и уходит
   `encode_signed`; узел без эпохи (`primary_epoch == 0`) хвост не отдаёт.
3. `handle_pull_response` до чтения фреймов требует: непустой `primary_epoch`; при
   `self.epoch() == Some(e)` — `resp.primary_epoch == e` и `from == membership.primary()`; при
   `self.epoch() == None` — `from` из `self.roster`; `resp.from_seq <= applied_seq + 1`; подпись
   кадра `verify_body(&from, domain::WAL, Kind::WalPullResponse, frame.body, sig)`. Иначе — тишина
   без изменения `applied_seq`.
4. `install_snapshot` после установки просит хвост у primary принятой эпохи, а не у отправителя
   снапшота: получатель принимает хвост только от primary, и прежний адрес оставил бы догон без
   ответа. Узел без членства по-прежнему просит у отправителя (холодный старт).
5. `crates/vecdht-wire/src/messages.rs`: матрица подписей в тесте; комментарий над
   `WalPullResponse` заменён на фактический.
6. Спека: §4.3 (parenthetical про «каждый WAL-фрейм»), §5.3 (строка 0x21), §9.4 (два места),
   §9.7, §9.8 — durable-фрейм не несёт ни эпохи, ни подписи; ответ несёт `primary_epoch` и
   подпись primary, дверь проверяет эпоху, автора и `from_seq`.

Тесты `crates/vecdht-node/tests/s94_tail.rs`: (2) флипается с «неподписанный ответ принят» на
«отвергнут»; новый `wal_pull_only_primary_is_accepted` проверяет на эпохе 1: подписанный primary
принят, member-не-primary отвергнут, чужая эпоха отвергнута, `from_seq` впереди отвергнут,
неподписанный отвергнут, продолжение от primary принято; новый
`cold_node_without_membership_trusts_only_roster` проверяет правило `epoch == None`: подпись
ростера принята, подпись не-ростера отвергнута. Догон после снапшота в тестах (3)/(4) адресуется
primary.

## Границы

Атрибуция отдельной записи остаётся незакрытой: подпись ответа доказывает «этот primary
засвидетельствовал этот хвост», а не авторство каждого `InsertOp`. Это принятое следствие
варианта B: durable-фрейм не меняется, иначе понадобился бы новый формат диска. Реплика может
отвечать на pull, но тёплый получатель такой ответ отвергает по гейту автора; серверного гейта
«только primary отдаёт» нет намеренно — иначе холодный узел без эпохи не смог бы добрать хвост у
seed'а, который не является primary. `SnapshotOffer` (D3) и подпись `Publish` (T1) этой карточкой
не трогаются.
