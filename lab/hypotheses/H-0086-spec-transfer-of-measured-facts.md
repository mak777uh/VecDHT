# H-0086 — перенос измеренного в текст спеки (первая правка по слову владельца)

## Право и его граница

Владелец 2026-10-23 сказал: «спеку модешь менять если видишь факты более полещные» — то есть правка
`docs/VecDHT-SPEC-v8.md` разрешена. Разрешение не отменяет инвариант замерного цикла: **внутри цикла,
где замораживаются пороги, `docs/` обязан оставаться нетронутым** (порог (0) каждой `H-*` требует
пустого `git diff` по `crates/*/src` и `docs/`). Поэтому перенос измеренного — отдельный цикл без
оракула и без замеров: у него нет чисел, которые можно опровергнуть прогоном, зато есть утверждения,
которые можно опровергнуть ссылкой. Замерный diff этого цикла — ровно спека, зеркало, ADR и документы.

**Что заменяет оракул.** Каждая правка обязана (а) цитировать experiment id и `файл:строку` продукта,
(б) быть проверяемой по логу: номер гейта из уже опубликованного `lab/logs/e00XX-all.log`, (в) не
содержать ни одного числа, которого в этих логах нет. Фальсификатор цикла: если хоть одна вставленная
формулировка не выводится из опубликованного замера — правка откатывается, а не «дообъясняется».

## Кандидаты и что именно менять

**1. §4.2 `:148…155` «Правила проверки» — список из шести пунктов против девяти ступеней.**
Нынешний текст перечисляет требования и молчит о порядке, тогда как порядок — часть семантики
(`E-0085`, гейты (2)…(4)): `cert.rs:116…144` проверяет `version` → `genesis` → `capacity > 0` →
`shards ≤ 64` → `valid_from` → `valid_until` → nonce вне отзывов → `sigs ≤ 16` → порог `t`, ступеней
девять, различных имён **восемь** (7 и 8 дают `BelowThreshold` с разными `have`), видимость ступени
`k` = `2^(8−k)` (`256,128,64,32,16,8,4,2,1` + `Ok=1`), `Revoked` остаётся видимым в 4 комбинациях из
256. Правка: к списку добавить абзац о порядке и о том, что имя отказа не является ни единственным на
причину, ни достижимым для части причин (декодер `vecdht-wire/src/cert.rs:78…112` отказывает тремя
ступенями раньше и добавляет четвёртое условие `valid_until ≤ valid_from`, которого в списке нет).
Сам список нормативных требований **не сокращается**: код требует больше, чем обещает спека, а не
наоборот.

**2. §4.2 `:159` «Отзыв» — дописать измеренные последствия.** Нынешняя фраза: «узел, увидев отзыв,
сбрасывает соединения и перестаёт подписывать что-либо этим ключом». По замеру (`E-0085`, гейты
(9a)…(9e), `service.rs:788…843`): снимается личность пира (`forget_peer`) и рвётся **исходящее**
соединение наблюдателя (`disconnect_peer_id`); соединение, начатое самой жертвой, живёт и её
прикладной кадр получает `DENIED:0:0`; `provider_peers` не сокращается никогда (`:672…678`, `:323…325`)
— кэш провайдеров шарда монотонен; «сколько живёт разрешение» — **развилка двух режимов**, а не
число (5 исполнений из шести дали `DENIED`, шестое — локальный отказ `send_frame`). Отдельно:
`E-0076` показал, что gossip-путь `Publish` в тему шарда ложится в индекс независимо от того, принят
ли handshake (`route_gossip`, `service.rs:982`), и `E-0085` воспроизвёл это на ветке `valid_from`
(гейт (6d)) — про это в §4.2 не сказано ни слова.

**3. §9.3 `:985` «пока сумма ≤ `capacity_entries`» — обещание без механизма.** Четвёртая подтверждённая
фикция этого семейства после §12.4/`NO_SUCH_SLOT` (`E-0065`), §16.3 (`E-0080`) и §19.4 «find»
(`E-0084`): держатель проверяется в пределах одного шарда (`Holder::fits`,
`crates/vecdht-node/src/candidates.rs:46…48`), `select` его не исключает; замер — `E-0085`, гейт (8):
`capacity = 1000`, по `900` на шард, держатель входит в оба состава. Правка в минимально честной
форме: строка получает явную пометку «в v1 правило пер-шардовое, суммарное — не реализовано» (по
образцу того, как §19.3 выносит незакрытые вещи за v1), **без** выдумывания механизма и **без**
удаления требования: removal — это решение владельца об объёме v1, а не факт замера.

**4. §19.5 `:1766` «~13 RPC» и отсутствие кванта опроса.** `E-0084` (гейты (10)/(11)): предельный
дополнительный шард = `0,836…0,898 × poll_interval`, `fanout13_to_one = 8,99…9,61` — то есть фан-аут
13 стоит не тринадцать RTT, а тринадцать квантов опроса, склеенных конвейером. Constant в продукте
есть: `poll_interval` по умолчанию **25 мс** (`service.rs:115`, `agent.rs:157`), стенд `E-0084`
работал на 5 мс; в спеке числа нет (`OPEN-QUESTIONS` п. 34). Правка: в сноске строки назвать единицу
(квант опроса узла) и его дефолт, не трогая арифметику `nprobe → шардов`.

**5. Что в этот цикл НЕ входит.** §19.4 (шесть строк таблицы целей) и §20.2/§14.4 — правки по
уже зарезервированным `ADR-0037`…`ADR-0041` (`OPEN-QUESTIONS` п. 29…34): там меняется не только
формулировка, но и конвенция слова «запас» (два значения, выведенные `S-0005`), поэтому им нужен
отдельный цикл `H-0087` с собственной проверкой цитат. §5.3/§6.7 `MODEL_MISMATCH` — тоже не здесь:
`ADR-0024` не принят, и менять обещанный код отказа без решения владельца значит переписать
требование по факту реализации. Ротация корпуса авторитетов не мерилась — не трогается.

## Пороги (замораживаются до коммита правки)

- (0) продуктовый код (`crates/*/src`), тесты и `lab/logs/*` этого цикла не тронуты: `git diff` пуст по
  этим путям; меняется только `docs/VecDHT-SPEC-v8.md`, зеркало, `lab/decisions/ADR-0042-*.md`,
  `lab/README.md` (реестр), `lab/PLAN.md`, этот файл и закрывающий `E-0086`.
- (1) каждая вставленная формулировка имеет ссылку вида `E-00XX гейт (N)` и `файл:строка`; число
  ссылок в diff ≥ числа новых утверждений (проверяется `grep -c 'E-00'` по добавленным строкам).
- (2) зеркало: `bash lab/check-spec-mirror.sh` → `OK` после `--fix`; число строк спеки и sha256
  оригинала записаны до и после.
- (3) ни одно замороженное число ни одной `H-*`/`E-*` в diff спеки не изменено и не удалено; проверка —
  `git diff` по спеке не содержит строк с «≤», «мкс», «мс», «МБ/с», если они не несут ссылку на замер
  этого цикла (список исключений печатается).
- (4) правка §9.3 `:985` обязана сохранять исходное требование (пометка «не реализовано в v1»), а не
  стирать его — то есть diff содержит исходную строку текста, изменённую только пометкой.
- (5) §4.2: число ступеней в новом тексте = 9, число имён = 8, доля `Revoked` = 4/256 — ровно как в
  `e0085-all.log` (гейты (2)…(4)); расхождение любого из трёх чисел с логом блокирует коммит.
- (6) `ADR-0042` существует, в нём записаны: что изменено, на каком замере, чего правка **не** делает
  (не вводит механизм там, где его нет, не меняет обещанный код отказа), и что остаётся решением
  владельца; номер до коммита не занят (`git grep -c 'ADR-0042' HEAD` = 0).
- (7) markdown/YAML: front matter этого файла и `E-0086` разбирается `yaml.safe_load`; `lab/README.md`
  отсортирован нисходяще по номерам ADR.
- (8) правка не добавляет в спеку ни одного числа, которого нет в опубликованных логах (проверка
  вычитанием: каждое новое число встречается в `lab/logs/e00*.log`).
- (9) RAM и диск меряются до и после (допуск ≥ 4 000 МБ / ≥ 15 000 МБ), `cargo` не запускается вовсе —
  дерево сборки этого цикла не меняется, поэтому полной верификации нет по прецедентам `S-0004`/`S-0005`
  (docs-only проверка: mirror + YAML + diff).

## Стоимость и ритм

Пять правок текста, ноль прогонов. Оценка: чтение четырёх spec-мест и трёх логов, формулировки,
зеркало, ADR — меньше цикла с оракулом; риск один — соблазн дописать «как надо» вместо «как
