# H-0033 — ноль столкновений при `nprobe = 4` на эталонном артефакте создан сеткой его
# центроидов, а не протоколом: дешёвый стенд `reference_artifact()` в этой точке физически не
# способен измерить зазор между двумя правилами выбора

## Гипотеза

`E-0032` снял на `reference_artifact()` (`crates/vecdht-artifact/src/centroids.rs`, строки-сетка,
где номер кластера зашит в первые две координаты — `centroids.rs:104-117`) при `nprobe = 4` средний
fan-out кластерного правила ровно `4.00`, ноль запросов из 256 со столкновением двух выбранных
кластеров в одном шарде из 16 и Jaccard 1.000 с шардовым правилом. Равномерная модель (четыре
кластера выбраны из 1024 наугад) предсказывает хотя бы одно столкновение в 8,57 % запросов, то есть
примерно в 22 из 256.

Отсюда утверждение: это свойство **стенда**, а не протокола. Ближайшие строки сетки различаются
преимущественно в первых двух координатах (в них лежит `(row, col)`-номер кластера), поэтому
ближайшие четыре строки рассеяны по далёким друг от друга индексам и почти никогда не попадают в
один блок из 16; на центроидах без такой сетки тот же запросный поток обязан давать столкновения и
fan-out строго меньше `nprobe`.

Следствие для метода (то, ради чего заводилась гипотеза): числа пункта (3) из `E-0032` у точки
`nprobe = 4` измеряют не «кластерное правило не уже шардового», а «этот стенд в этой точке не
измеряет ничего». Если это так, все будущие измерения fan-out надо снимать либо на центроидах без
сетки, либо на реальном корпусе, и `reference_artifact()` годится только как проверка формы данных.

Утверждение (проверяемое ядро), три части:

1. воспроизведение: на сетке эталона при `nprobe = 4` столкновений `0` из 256 запросов;
2. на случайных `i8`-центроидах того же размера (`NLIST × DIM`, тот же LCG-поток запросов) при
   `nprobe = 4` есть хотя бы одно столкновение, и их доля не меньше 4 % запросов, а средний fan-out
   кластерного правила строго меньше `4.00`;
3. контроль идентичности стендов: на случайных центроидах шардовое правило (§7.5.1, минимум по 16
   строкам) по-прежнему отдаёт ровно `nprobe` шардов на всех запросах — то есть расхождение из
   пункта (2) не вызвано поломкой контрольной копии правила.

## Фальсификатор

Достаточно одного:

- **(а)** на случайных центроидах при `nprobe = 4` столкновений тоже ровно 0 из 256 — тогда дело не
  в сетке, а в более общем свойстве ближайших соседей в 384-мерной `i8`-сетке (случайные векторы
  почти равноудалены), и стенд с сеткой тут ни при чём;
- **(б)** на случайных центроидах средний fan-out кластерного правила при `nprobe = 4` не меньше
  `4.00` — зазора нет и там, значит вывод «стенд не измеряет» ложен;
- **(в)** на случайных центроидах шардовое правило не отдаёт ровно `nprobe` — прогон неинтерпретирем,
  ни один из выводов о стенде из него не следует (это дефект измерения, а не опровержение).

## Оракул

`crates/vecdht-artifact/tests/stand_grid_degeneracy.rs` (новое; корпуса, `candle` и сети нет):

1. два стенда центроидов одинакового размера — `reference_artifact().centroids` (сетка) и
   `Centroids::from_i8()` на LCG-байтах (случайные строки);
2. тот же детерминированный поток из 256 запросов, что и в `E-0032`;
3. для `nprobe ∈ {4, 16, 32}` и каждого стенда: доля запросов со столкновением (выбрано `nprobe`
   кластеров, а шардов меньше), средний fan-out обоих правил, средний Jaccard двух множеств шардов;
4. печати идут до проверок, чтобы фальсификатор (а) можно было отличить от (в) по числам.

## Порог (фиксируется до прогона)

(1) сетка, `nprobe = 4`: запросов со столкновением ровно 0 из 256; (2) случайные центроиды,
`nprobe = 4`: запросов со столкновением не меньше 11 из 256 (4 %) **и** средний fan-out кластерного
правила строго меньше 4.00; (3) случайные центроиды, все три `nprobe`: шардовое правило отдаёт ровно
`nprobe` на всех 256 запросах. Провал (2) при (3) исправном = фальсификатор (а)/(б): гипотеза
опровергнута, и тогда зазор при `nprobe = 4` — свойство выбора ближайших соседей вообще, а не сетки.
Провал (3) = (в): прогон объявляется неинтерпретируемым, гипотеза остаётся `proposed` с записанным
дефектом стенда. Порог (1) воспроизводит уже снятое число, он не может «опровергнуть» гипотезу и
нужен только чтобы два стенда сравнивались на одном запросном потоке.

## Входы и окружение

Дерево после `9c7d41a`, debug, `-j 2`, `RAYON_NUM_THREADS=2` (идёт тяжёлая рука `E-0027`). Числа
относятся к структуре выбора, recall не измеряется. Равномерная модель (8,57 % / ≈22 из 256) —
расчёт, а не замер; она используется только как ориентир для порога (2), порог же — 4 % (не меньше
11 запросов), чтобы не завязывать вердикт на модель, которая сама является предметом проверки.
