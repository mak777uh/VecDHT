# `lab/library/` — контур источников

Каталог живёт по правилу: **у утверждения, которое пришло не из нашего замера, есть строка в
индексе.** Либо строка есть, либо утверждение помечено как непроверенное и не переносится в спеку.
Индекс — `index.jsonl`, по одному JSON-объекту на строку, инструмент — `lab/library.py`.

## Зачем он в проектном (не научном) цикле

В научном цикле литература говорит, *что мерить и как называть*. В системном проекте она делает
две другие вещи, и обе стоят цикла:

* **готовая конструкция вместо перебора.** Пример из первого же применения (`L-0001`,
  [arXiv:1608.01350](https://arxiv.org/abs/1608.01350)): предел загрузки ячейки в литературе
  задаётся как `⌈c·m/n⌉` от **средней** загрузки, а его цена измеряется **числом перемещений**.
  Мы же искали форму капа перебором 256 булевых форм (`E-0079`) и остановились на 143 с
  **абсолютным** пределом; относительная форма масштаб-инвариантна, и это меняет постановку
  следующего цикла до заморозки его порогов.
* **чужая модель атаки вместо моей догадки.** Пример (`L-0002`,
  [arXiv:2604.05480](https://arxiv.org/abs/2604.05480)): §14.4 (iv) описывает надувание кластера
  как «много записей в одном центроиде», а опубликованная атака вставляет **несколько** векторов
  около геометрического центра и заявляет до 94,4 % успешных запросов; устойчивой защиты в
  литературе нет (открытая проблема). Наш кап от этого не защищает и защищать не обещает.

## Формат записи

```json
{"id": "L-0001", "title": "...", "url": "https://arxiv.org/abs/...", "cite": "arXiv:1608.01350",
 "verified": "2026-10-23", "depth": "аннотация", "gives": "что именно даёт работе",
 "targets": ["PLAN", "SPEC:§14.4"], "status": "не использован", "action": "",
 "cost_min": 0, "opened": "2026-10-23"}
```

| Поле | Обязательность | Смысл |
|---|---|---|
| `id` | формат `L-NNNN`, уникален | ссылка из гипотез и ADR |
| `url`, `cite` | https + устойчивый идентификатор | «ссылка важнее пересказа» |
| `verified` | дата `YYYY-MM-DD`, не в будущем | когда сверено, что id существует и это та работа |
| `depth` | `аннотация` / `текст выборочно` / `полный текст` | конспект не равен оригиналу |
| `gives` | непустое | что даёт именно нашему решению, а не «статья про хеширование» |
| `targets` | существующие в репо цели: `H-`, `E-`, `S-`, `ADR-`, `PLAN`, `OPEN-QUESTIONS`, `SPEC:§…` | к какой задаче источник привязан |
| `status` | `не использован` / `в работе` / `изменено` / `не повлияло` | «прочитал и не повлияло» — тоже результат, но с причиной |
| `action` | для `изменено` — ссылка на изменённый артефакт; для `не повлияло` — причина | инсайт без действия не считается прочитанным |
| `cost_min` | целое, `<= 30` | бюджет одного шага сверки; без него чтение превращается в отговорку не мерить |

## Команды

```bash
python lab/library.py check          # схема + инварианты; exit 1 при любом нарушении
python lab/library.py digest         # что не использовано, что висит, какие § спеки без сверки
python lab/library.py scan           # триггерные фразы спеки по разделам
python lab/library.py verify         # сверка arXiv-id с самим arXiv (название обязано пересечься)
python lab/library.py value          # счётчики полезности и вердикт по замороженному критерию
python lab/library.py add --json '{...}'
python lab/library.py use L-0001 --target H-0088
python lab/library.py close L-0001 --action изменено --what "..." --cost 12
```

Триггерные фразы, по которым `digest` задаёт вопрос («СПРОСИ §…»): «защиты нет», «не реализовано»,
«не измерено», «не проверя», «нет механизма», «не выполнено», «обещание», «не достаточн». Это ровно
те слова, которыми мы описываем дыры, — и чаще всего под такой формулировкой уже есть работа.

## Критерий полезности (заморожен до применения, `ADR-0045`)

Контур считается полезным, если **на каждые 5 закрытых записей хотя бы одна помечена `изменено`**
и средняя стоимость шага не превышает бюджета 30 минут. Если после пяти записей `изменено = 0`,
контур признан декоративным — обязательность снимается отдельным коммитом, а индекс остаётся как
справочник. Проверка машинная: `python lab/library.py value --cycles 5`.

## Чего контур НЕ делает

1. **Литература не становится фактом спеки.** В `docs/VecDHT-SPEC-v8.md` попадают только числа и
   поведения, полученные нашим прогоном, с номером `E-`. Чужой результат — запись в индексе и (при
   необходимости) новая гипотеза; в спеке он может существовать только как «по литературе …, у нас
   не проверено».
2. **Не переносит абсолютные числа.** Статьи меряют IVF/ANN на одной машине, без шардов, PoW-гейта
   и WAN. Наш собственный опыт (`E-0082`) показывает, что даже наши абсолютные микросекунды —
   снимок хоста. Из литературы берём форму, единицу цены и невозможность, не шкалу.
3. **Не заменяет оракул.** Ни один вердикт цикла не переведён в `supports`/`refutes` ссылкой на
   статью; порог, изменённый литературой, меняется **до** пре-регистрации и замораживается вместе
   с остальными (`E-0079`, правило «пороги не двигаются задним числом»).
4. **Не хранит полные тексты и не переводит чужие статьи.** Только метаданные, ссылку, наш конспект
   и короткие атрибутированные цитаты.
5. **Не заводит второго круга циклов.** Если источник просит проверку, он рождает запись в очереди
   (`OPEN-QUESTIONS`/`PLAN`), а не ответ по памяти в этом же цикле.
