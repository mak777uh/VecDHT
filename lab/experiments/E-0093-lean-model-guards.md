# E-0093 — страж моделей: аксиомы по терминам доказательств, формулировки под заморозкой

## Что замораживается до прогона

Таблица ожиданий — файл `lab/expectations/e0093.tsv` (23 строки, по одной на печатный ключ),
сверка по нему — `python lab/expect.py`. Ключевые строки:

| Ключ (печатается именно так) | Ожидание |
|---|---|
| `LEANGUARD_SELFTEST total` / `passed` | 10 / 10 |
| `SELFTEST_EXIT` | 0 |
| `PRE_FIX_axiom_EXIT` / `PRE_FIX_axiom_LEAN_ALL_OK` | 0 / 1 |
| `PRE_FIX_weaken_EXIT` / `PRE_FIX_weaken_LEAN_ALL_OK` | 0 / 1 |
| `WRAPPER_EXIT` / `WRAPPER_LEAN_FILE_COUNT` | 0 / 5 |
| `VECTOR_1_EXIT` / `VECTOR_2_EXIT` | 0 / 0 |
| `repro_вектор` | совпал |
| `LEAN_TOTAL` / `DECLS_TOTAL` | 5 / 115 |
| `BROKEN` / `SORRY_TOTAL` / `SORRYAX_TOTAL` | 0 / 0 / 0 |
| `NATIVE_AXIOMS` / `STD_AXIOMS` / `CUSTOM_AXIOMS` / `AXIOM_FREE` | 93 / 18 / 0 / 4 |
| `DIGEST_BAD` / `LEAN_ALL_OK` | 0 / 1 |

Сверка ищет ключ как отдельный токен, а значение — до границы следующего слова, и потому не проходит
случайно: ожидание `LEAN_ALL_OK=1` не удовлетворяется строкой `PRE_FIX_axiom_LEAN_ALL_OK=1` (это
доказательство слепоты прежнего прибора, а не годовости нового), а `NATIVE_AXIOMS=9` не удовлетворяется
строкой `NATIVE_AXIOMS=93`. Отсутствующий ключ = расхождение. Проверено четырьмя посадками на
искусственном корпусе до пре-регистрации: годный вектор даёт `РАСХОЖДЕНИЙ=0` и выход 0, вырезанная
итоговая строка, подменённое число и `passed` в чужой строке дают выход 1, пустые факты — выход 2.

Числа (115 / 93 / 18 / 4) сняты разведкой до пре-регистрации и замораживаются здесь как ожидание, а
не выводятся из результата прогона. `AXIOM_FREE=4` — это «4 декларации не зависят ни от чего, кроме
собственного терма», а не «4 теоремы из 115»: остальные распределены между `native_decide` (93) и
тремя стандартными аксиомами (18).

## Форма гейта, которую нельзя перепутать с успехом

* отбит «по своей причине» = в выводе прибора есть строка `ПРОТИВ <модель>: <код этой причины>`.
  Код, а не подстрока счётчика: `SORRY` совпало бы с `SORRY_TOTAL=0` в сводной строке и удовлетворил
  бы гейт, который вообще ничего не нашёл, поэтому ожидание — `SORRY:` с двоеточием;
* молчание прибора = провал: `UNSEEN` по декларации, по которой не распечаталась ни одна из двух
  положенных строк, и `PARSER` при несовпадении числа строк `theorem`/`lemma` с числом разобранных
  имён;
* посадка обязана быть подтверждена: мутаторы `__weaken__` и `__drop__` падают с текстом «посадка не
  сработала», если не нашли свою строку в модели. Без этого «дефект отбит» мог означать «дефекта не
  было».

## ДИАГНОЗы пре-регистрации (замерены, а не предсказаны)

**ДИАГНОЗ-1 — прибор, который врал про пользу.** `grep -c axiom` по пяти моделям = 0,
`#print axioms` по 115 декларациям = 93 зависимости от аксиомы `native_decide`. Прежний страж физически не мог этого увидеть: он читал текст файла. Формулировки «формально проверено» в
`E-0078`/`E-0079`/`E-0085`/`E-0092` верны, но неполны, и уточнение вносится в README и в статью
отдельной правкой.

**ДИАГНОЗ-2 — самопроверка, которая не находила образец.** Первый запуск `selftest` из черновиков
копировал модели из `dirname(HERE)/lab/lean/VecDHT`, которого рядом с черновиком нет: мутатор
работал по несуществующему файлу, а контроль «голое дерево» проходил на пустом каталоге. Теперь
`_tree` бросает ошибку при нуле скопированных моделей, а `cmd_selftest` отказом отвечает
«нечего сажать». Позитивный контроль на пустом дереве — это зелёное враньё, и оно было найдено
только потому, что контроль есть.

**ДИАГНОЗ-3 — кириллица в выводе прибора.** Первый полный прогон selftest отбил дефекты по коду
возврата, но «не по своей причине»: Windows-локаль заставила дочерний процесс писать cp1251, родитель
читал UTF-8, и подстрока «изменена после заморозки» не совпала с той же строкой в mojibake.
Исправлено явно: `PYTHONIOENCODING=utf-8` в окружении дочерних вызовов, `encoding="utf-8"` при
чтении, `sys.stdout.reconfigure` в начале `main()`. Правило: если причина отказа ищется по тексту,
кодировка текста — часть надёжности гейта.

**ДИАГНОЗ-4 — сирота доказательства.** Мутатор «теорема удалена» срезал только строку
`theorem … := by`, оставляя следующую за ней `  native_decide`. Модель переставала компилироваться, и
дефект отбивался по чужой причине (`COMPILE` вместо `STATEMENT`). Теперь снимается вся декларация
вместе с отступными строками доказательства.

**ДИАГНОЗ-5 — сверка, способная пройти чужим доказательством.** Первая версия `lab/expect.py` искала
ожидание как подстроку. На проверочном корпусе (он снят до пре-регистрации, четыре посадки) это дало
два ложных прохождения: `LEAN_ALL_OK=1` считалось выполненным строкой `PRE_FIX_axiom_LEAN_ALL_OK=1` —
то есть гейт «новое дерево годно» удовлетворялся бы замером дыры прежнего прибора, — а `NATIVE_AXIOMS=9`
считалось выполненным строкой `NATIVE_AXIOMS=93`. Теперь слева от ключа обязано стоять начало строки
или пробел, справа от значения — граница слова, отсутствующий ключ = расхождение (не «не совпало, и
ладно»), а пустой файл фактов = отдельный выход 2. Правило переносимое: у сверки чисел надо проверять
не только само совпадение, но и **чем именно** оно обеспечено; проверка на ложные прохождения — часть
прибора, а не украшение.

## ДИАГНОЗы прогона (замерены, а не предсказаны)

**ДИАГНОЗ-6 — повторяемость, которую красит время.** Первый прогон дал `repro_вектор=РАЗОШЁЛСЯ` при
полностью совпавших числах: сравнение было побитовым, а в вывод входят `MS=` по каждой модели и
`LEAN_MS_TOTAL=`. Время прогона окружение цикла объявило ценой, а не гейтом, — значит сравнивать по
нему вектор нельзя. Починка: сравнение без колонок времени, разброс печатается числом, чтобы замер
не был спрятан. Правило переносимое: если поле объявлено ценой, оно обязано быть исключено из всех
равенствных гейтов, а не только из порогов.

**ДИАГНОЗ-7 — потерянная строка в корпусе сверки.** Фильтр, собиравший корпус для `lab/expect.py`,
брал строки, начинающиеся с `LEAN_TOTAL=` и `LEANGUARD_SELFTEST `, а прибор печатает `LEAN_ALL_OK=`
отдельной строкой после сводной. Сверка сообщила «РАСХОЖДЕНИЕ: LEAN_ALL_OK … нет такого ключа» и
`СВЕРКА_EXIT=1` — дефект корпуса обнаружился как честный провал, а не как молчаливое прохождение.
Тот же класс, что ДИАГНОЗ-3 у `E-0087` (обрыв регрессии вместо прогона): проверяющий код обязан
уметь сказать «я ничего не нашёл», и отсутствующий ключ трактуется как расхождение.

**ДИАГНОЗ-8 — осевший каталог после прерванного запуска.** В временном хранилище нашёлся каталог
`leanguard-*` с восемью подкаталогами внутри и временем модификации 00:54 — то есть от запуска,
который не дошёл до конца: `selftest` сносил дерево-копию только в конце удачной ветки, любое
прерывание оставляло его. Починка — регистрация уборки на выход процесса; helper печатает счётчик
осевших каталогов до и после шага (`SELFTEST_осевших_каталогов_до=0 после=0`). Ограничение:
проверена только удачная ветка, принудительного исключения в прогоне не было — утверждать, что
уборка работает на всех аварийных выходах, этот цикл не вправе.

## Что этот цикл НЕ измеряет

Не переносит 93 теоремы на ядерный `decide` (разведка: `Denylist.lean` — 18 вхождений заменимы
целиком за ~4 с, `CertLadder.lean` — на 256-векторных теоремах `decide` падает по глубине рекурсии;
это отдельный цикл). Не доказывает, что формулировка выражает задуманное: дайджест даёт только
«не изменена тайно» (`L-0011`). Не трогает ни одну из пяти моделей.
