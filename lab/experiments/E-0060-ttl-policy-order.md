# E-0060 — полный набор проверок `Spend::consume` и его порядок: подпись → адресат → политика TTL → истечение → расход (§12.3)

## План прогона

Оракул `crates/vecdht-node/tests/ttl_policy_order.rs`, helper `lab/e0060-run.sh`
(helper исполняет команду целиком — урок `e0049`; структура секций как в зелёных
`e0058`/`e0059`: BUILD `--no-run` → RUN `--nocapture` → ИНВЕНТАРЬ → КОНТРОЛЬ
`-p vecdht-node`). Харнес — одиночный primary, живой приём бакета 0 из-под `Find`,
подделки — переиздание тела с другим `ttl_sec` и честной подписью издателя
(`sign_body(domain::RENDEZVOUS)`); расход — прямой `Spend::consume` (без входа
`present`: мерится приёмная сторона, а не гейт `ADR-0013`).
Лог: `lab/logs/e0060-all.log` (append-only). Пороги заморожены в `H-0060` до первого
замера; коммит пре-регистрации пушится до измерений.

## Прогон

Три падших прогона харнеса (14:43, 14:50, 14:59) — артефакты привязки вызова, пороги не
затронуты: `consume` требует `issuer = n.me()` (приёмку подписывает ключ узла,
`node.rs:1019`) и `me = acc.target` (адресат карты = владелец записи), как в зелёных
`adversarial.rs:381-386`/`E-0058`. ДИАГНОЗ/ДИАГНОЗ-2/ДИАГНОЗ-3 append в `e0060-all.log`.

Первый зачётный прогон (rev `6cc37f5`, 15:04) прошёл пороги (0)…(7) и упал на (8):
`spent == 1` дало 0. Причина — порог (5) предъявлял кадр при `now = 301`, а `consume`
первым делом `prune(now)` (семантика `E-0059`): запись расхода бакета 0 (`expires = 20`)
вычищена до более поздних проверок. Поправка заморозки — append в `H-0060` (сильная
форма: ветки порядка на живом `now = 19`, новые различающие пороги (8) `Expired` +
`spent == 0` ровно на `expires`, (9) чистая цель, (5) в конце с зондом `spent == 0`;
фальсификаторы (и)/(й)/(к)). Оракул переготовлен `--no-run` + clippy до коммита поправки.
