## Pre-registration (до прогона)

§16.3 — единственное место спеки, где описан путь деградации целиком и одновременно заявлено,
что отдельного протокола для него нет: «агент видит пустой DHT-ответ по ключу шарда, повторяет
lookup с backoff и, если шард пуст, пишет интент первому узлу, готовому взять эпизоду (§9.3)».
Цикл спрашивает не «есть ли код» (его нет по построению), а **выполнимы ли три условия**, из
которых обещание состоит, — и по порядку их проверяет.

Второй цикл подряд по правилу владельца: модель пишется **до** замера и номинирует, что мерить.
`lab/lean/VecDHT/Shard.lean` (399 строк, 25 теорем, 25 `native_decide`, 0 `sorry`,
`LEAN_EXIT=0` за 2563 мс) делает три вещи, которые нельзя получить прямым наблюдением кода:

1. `no_local_readiness` — перебор всех 64 конъюнкций шести локальных признаков даёт **пустое
   множество**: не существует условия «готов взять эпизоду», истинного на узле без эпизоды и
   влекущего приём записи. Причина — `implyingForms_are_sixteen` и
   `no_intersection`: все 16 влекущих приёма форм содержат `{isPrimary, lease}`, то есть уже
   принятую эпизоду. Третий подпункт §16.3 невыразим, а не «не реализован».
2. `only_authorities_open_genesis` + `lowering_the_threshold_only_removes_it = [0, 1]` —
   единственный источник эпохи 1 — порог авторитетов; понижение порога не даёт узлу права
   открыть эпоху, а снимает требование подписи (t = 0) либо допускает его собственную (t = 1).
3. Перебор 72 сеток повторов lookup: `coverage_is_the_last_query` (покрытие = момент последнего
   запроса), `coverage_top_is_one_second_step` (19/20 только при шаге 1 с),
   `same_coverage_three_times_the_traffic` (текущий шаг 3 с покупает покрытие 18 шестью
   запросами там, где `(6, 2)` покупает его двумя), `min_delay_among_covering_is_fixed_step`
   (минимальная задержка — при `factor = 1`, то есть фиксированный шаг лучше экспоненциального)
   и `tail_is_never_covered`. «Backoff» из спеки — слово для того, чего в коде нет, и перебор
   показывает, что то, что в коде есть, по задержке даже лучше.

Отдельная методическая находка цикла: **узел отказывает до проверки nonce**
(`node.rs:723` раньше `node.rs:741`), поэтому утверждение «агент всё равно оплатил PoW» нельзя
вывести ни из поведения узла, ни из тайминга (ДИАГНОЗ-5 из `E-0079`). Оно выводится только из
декодированного кадра: оракул ставит сниффера — index-node с подлинным `NodeCert`, который шард
не держит, отвечает `MatchResult{epoch = 0}` и записывает байты `Publish`; `pow_ok` считается
дважды, под эпохой 0 и под эпохой 1.

Цена попытки измеряется **числом пойманных `Publish`**, а не временем — это прямое следствие
`outcome_is_order_free` / `cost_is_order_sensitive` из модели. Время остаётся ровно одним
порогом и ровно в одной роли: «названная узлом пауза в 9 с не выдержана», где ожидаемое
значение меньше порога в ~12 раз.

Ожидаемый результат: (1)…(9) зелёные, §16.3 раскрывается как четвёртое обещание без механизма,
причём рвётся оно не на «отсутствии протокола деградации» (его и не должно быть), а на
предпосылке: «пустого DHT-ответа» не наступает, потому что узел объявляет провайдинг по
кредашиалу (`service.rs:934…942`), а агент фильтрует кандидатов по кредашиалу же
(`agent.rs:1079…1135` → `handshake.rs:70`), не по членству.
