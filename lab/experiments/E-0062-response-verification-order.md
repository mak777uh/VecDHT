# E-0062 — порядок проверок `session::verify_response` (§12.4) и немедленные отказы входа цели (§12.3): непокрытые `TextError::WrongKind`/`Malformed`

## План прогона

(структура секций как в зелёных `e0060`/`e0061`: BUILD `--no-run` → RUN `--nocapture` →
ИНВЕНТАРЬ → КОНТРОЛЬ `-p vecdht-node`; helper исполняет команду целиком — урок `e0049`).

вид 0xFE, усечение, `sig_len` 63, отсутствие подписи при ложном владельце, ложный ожидаемый

СОСТОЯЩИМ на момент замера (с этим оракулом: `Malformed` 6, `WrongKind` 4); до

## Что это значит

Порядок, который §12.4 называет явно, жив на каждом шаге и различим по ИМЕНИ отказа, а не
только по факту отказа: вид кадра раньше подписи (табличный чужой вид даёт `WrongKind` и на
подписанном, и на без-подписном кадре), заголовочные гейты раньше всего (`0xFE`, усечение,
`sig_len` 63 → `Malformed` — та же арифметика, что измерил `E-0061` на приёме), наличие
подписи раньше владельца (ложный владелец без подписи → `Unsigned`, не `WrongOwner`), разбор
тела раньше владельца (сверхлимитный текст при чужом ожидаемом ключе → `Malformed`, не
`WrongOwner`), и владелец раньше криптографии: кадр с ИСПОРЧЕННЫМ текстом и ложным
ожидаемым владельцем даёт `WrongOwner`, то есть подпись чужого ключа действительно «не
считается» — ровно обещание docstring'а и спеки. Лимит 1000 байт на двух концах зовётся по
разным именам (`Malformed` на разборе против `TextTooLong(1001)` на подписании), и это
фиксировано различающим порогом (8)/(10): собственная ветка `TextTooLong` в
`verify_response` — мёртвый симметричный повтор, живой гейт — декодер поля. На входе цели
немедленные отказы `consume` (`Malformed`, `WrongKind`) проходят наружу как
`TextError::Spend(...)` без маскировки в `NotSignedByShardHolder` — обещание §12.3 «перебор
кандидатов только по `BadSignature`» подтверждено в обе стороны (перебор из `E-0051`, немаскировка
из этого замера), адресат сверяется раньше требования предъявления (`WrongTarget`, не
`NoAccept`), и ни один немедленный отказ не тронул память расхода (`spent == 0`).
Расхождения спека↔код не обнаружено — правка спеки не нужна.

## Границы

Мерялись две экспортируемые функции (`verify_response`, `serve_request`) на кадрах,
полученных мутацией честных байтов; криптостойкость Ed25519 и пере-подпись живого приёма —
территория `adversarial.rs`/`E-0060`. Первая клауза порогов (5)/(6) (базовые `Unsigned`/
`WrongOwner`) ассертится юнит-тестами модуля, на входе оракула — различающие комбинации; это
оговорено выше и не меняет замороженной формулировки. Лимит 512 Б на поле `present` не
измерялся (покрыт `present_serving_gate.rs`, порог (6)); фикстура (13) выбрана внутри
лимита. `TextError::Structured`/`Markup`/`LineBreak`/`Control`/`Empty`/`TooLong` относятся к
разметке текста, а не к порядку проверок. Часы не двигались (`now_bucket = 0`) — окно и
память расхода здесь не меряются (`E-0047`/`E-0058`/`E-0059`/`E-0060`). Маскировка
`AlreadySpent` при списке без прежнего издателя (кандидат на ADR из `E-0054`) здесь не
проверялась — не смешивать с немаскировкой немедленных отказов.
