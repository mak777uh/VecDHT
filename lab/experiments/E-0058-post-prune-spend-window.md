# E-0058 — окно расхода post-prune приёма: Ok на 39, Expired на 40, синхронно с дырой издателя

## План прогона

Оракул `crates/vecdht-node/tests/post_prune_spend_window.rs`, helper `lab/e0058-run.sh`
(helper исполняет команду целиком — урок `e0049`; структура секций как в зелёных
`e0056`/`e0057`: BUILD `--no-run` → RUN `--nocapture` → ИНВЕНТАРЬ → КОНТРОЛЬ
`-p vecdht-node`). Харнес — одиночный primary + `Spend` тестовой цели; post-prune
приёмы бакета 20 получены живым `Find`-путём после prune 100 000 строк бакета 0.
Лог: `lab/logs/e0058-all.log` (append-only). Пороги заморожены в `H-0058` до первого
замера; коммит пре-регистрации пушится до измерений.

## Прогон

Один зачётный прогон `e0058-run.sh` (rev `9a62f04`, BUILD `--no-run` EXIT=0 → RUN
`--nocapture` EXIT=0, 17.6 с → ИНВЕНТАРЬ → КОНТРОЛЬ `-p vecdht-node` EXIT=0). ДИАГНОЗ'ов
нет: все пять порогов совпали с замороженными предсказаниями с первого замера. Числа:
`consume(A20)@39` → `Ok` (grant связан с A/бакетом 20), повтор → `AlreadySpent`,
`@40` → `Expired`; побратим B20 того же слота → `Ok` @39 и `Expired` @40; живой `Find@40`
→ 3 НОВЫХ строки бакета 40 (байты ≠ A20), `live == 3`. Инвентарь подтвердил обе границы
из одной величины: `prune` — `cutoff = now − buckets(300)`, `consume` — `Expired` при
`now > issued + buckets(ttl)`, память расхода `expires = issued + ttl + 1`.
Верификация воркспейса: 564 ok / TEST_EXIT=0 / CLIPPY_REAL_EXIT=0.

## Что это значит

Двенадцатое подтверждение §12.3 подряд: синхронность границ издателя и цели — свойство,
а не совпадение. Приём, выписанный ПОСЛЕ prune (бакет 20), живёт в расхода ровно до
бакета 39 включительно и истекает на 40 — тем же бакетом, в котором `Issuer::prune`
выбрасывает его строку (`cutoff = 40 − 19 = 21 > 20`). Цель не может принять то, что
издатель уже не хранит, и не может отвергнуть то, что издатель ещё хранит: обе границы
выведены из одного `buckets(ttl_sec)`, и docstring `prune` («граница выбрана строго по
`Spend::consume`») теперь измерена с обеих сторон и на post-prune ветке. Побратим на том
же слоте, но с другим seeker'ом, расходуется независимо (`E-0055`-свойство сохраняет
силу и после prune). Правка спеки не нужна: §12.3 не обещает ничего противоречащего,
а обещанное подтверждено.

## Границы

Мерялся бакетный скелет синхронности (Ok/AlreadySpent/Expired на двух гранях + живой
prune-путь) на одиночном primary с `Spend::new(300)`; `ttl_sec` кадра фиксирован политикой
(300) — других окон не меряли. Реальная сеть/ротация эпохи на post-prune приёме не
проверялись (ротация `E-0050`/`E-0054` меряла прежнего издателя, не prune-бакеты).
