## Что добавляется в стенд (протокол не тронут)

Режим `VEC_DHT_P0_SUB=<s>` поверх гейтной карты `E-0012`. Новый объект существует только в стенде:
для каждого из 1024 мелких кластеров строятся `m` целочисленных sub-центроидов (farthest-first по
`l2_sq` над уже квантованными int8-векторами участников кластера, затем Lloyd с целочисленными
средними и округлением вверх при .5, до отсутствия изменений или 16 итераций). Присваивание участника
подсписку — int8-argmin по sub-центроидам с разрывом равенства по id подсписка, то есть контракт
детерминизма ровно тот же, что у §7.2 для кластеров.

Скан: ≤ 16 ячеек выбираются гейтным правилом §7.5.1 (минимум `l2_sq` по 16 мелким центроидам),
в каждой ячейке берутся все 16 кластеров, и в каждом кластере — `s` ближайших подсписков
(сортировка по `(l2_sq(query, sub_centroid), sub_id)`). При `s = m` множество записей совпадает со
множеством полного скана, поэтому контроль `s = m` обязан дать числа `E-0012`.

Отбор остаётся целочисленным и contract-определимым, поэтому §8.4 (две корректные реализации дают
побайтово одинаковый `MatchResult`) не нарушается даже в этом стендовом варианте — в отличие от
графа, который предлагался внешне (`docs/VecDHT-v9-REVIEW.md`, п. 2.4).
