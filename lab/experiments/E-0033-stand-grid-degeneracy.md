# E-0033 — ноль столкновений при `nprobe = 4` создан сеткой центроидов эталона, а не протоколом

## Гипотеза

См. `H-0033`.

## Стенд (правок измерительного гейта нет)

Новый тестовый файл `crates/vecdht-artifact/tests/stand_grid_degeneracy.rs`: два стенда центроидов
одинакового размера `NLIST × DIM` — `reference_artifact().centroids` (строки-сетка, где номер
кластера зашит в первые две координаты) и `Centroids::from_i8()` на байтах другого LCG-потока
(случайные строки, никакого кода номера). Запросный поток — тот же seed и та же схема, что в
`fanout_rule.rs` (`E-0032`), 256 запросов, чтобы точки были сравнимы с прошлым прогоном. Для каждого
стенда и каждого `nprobe ∈ {4,16,32}` снимаются: число запросов, где `nprobe` кластеров легли в
меньшее число шардов (столкновение), средний fan-out кластерного правила, средний fan-out шардового
правила и средний Jaccard двух множеств шардов. Правок `IvfIndex::search`, `Find`, гейтных порогов и
стенда `p0_real_corpus.rs` нет; recall не измеряется.

## Прогон

Одно усилие, `lab/e0033-run.sh` на дереве `fa79673` (пре-регистрация была залита до запуска, оракул
до прогона только компилировался `--no-run`), 35,1 с, `EXIT=0`:

```
сетка эталона    nprobe=4 : столкновений 0/256, кластерное 4.00, §7.5.1 4.00, Jaccard 1.000
случайные строки nprobe=4 : столкновений 18/256, кластерное 3.93, §7.5.1 4.00, Jaccard 0.982
сетка эталона    nprobe=16: столкновений 227/256, кластерное 13.30, §7.5.1 16.00, Jaccard 0.832
случайные строки nprobe=16: столкновений 226/256, кластерное 14.35, §7.5.1 16.00, Jaccard 0.897
сетка эталона    nprobe=32: столкновений 256/256, кластерное 17.91, §7.5.1 32.00, Jaccard 0.560
случайные строки nprobe=32: столкновений 256/256, кластерное 25.86, §7.5.1 32.00, Jaccard 0.808
```

Контроль `cargo test -j 2 -p vecdht-artifact`: зелёный целиком (37 + 1 + 4 + 3 + 2 + 1), то есть
оракул `E-0032` после переписки в описание измеренного тоже проходит. В логе тем же скриптом лежит
расчёт равномерной модели (8,57 % / 85,49 % / 99,99 % для `k = 4/16/32`), он помечен как расчёт.

## Результат

Гипотеза подтверждена по всем трём порогам. Нулевой зазор кластерного правила при `nprobe = 4` на
эталонном артефакте — свойство его сетки центроидов: на случайных `i8`-строках того же размера и при
том же запросном потоке столкновения появляются (18 из 256) и средний fan-out становится строго
меньше `nprobe` (3.93), а шардовое правило остаётся ровно `nprobe`, так что объяснять это поломкой
контрольной копии нечем. Значит точка `nprobe = 4` из `E-0032` не измеряла «правила не различаются» —
она измеряла отсутствие различий в самом стенде.

Числа ложатся на равномерную модель там, где стенд ничего не кодирует: 7,0 % против предсказанных
8,57 % при `k = 4`, 88,3 % против 85,5 % при `k = 16`, 100 % против 99,99 % при `k = 32`. Сетка
эталона, наоборот, от модели уводит: при `k = 32` она даёт 17.91 шарда вместо 25.86 на случайных
строках, то есть рассеивает выбранные кластеры шире, чем это бывает у настоящих центроидов.

Побочное наблюдение, не входившее в пороги и потому не вердикт: `nprobe = 16` на случайных
`i8`-центроидах даёт 14.35 шарда и столкновения почти на всех запросах — величина, которая уже
измерялась на реальных корпусах (`E-0004`: 14.3, `E-0006`: 14.4). Дешёвый стенд без корпуса и без
`candle` воспроизводит fan-out реального корпуса с точностью до сотых, поэтому он годится как
прибор для измерений ширины выборки; `reference_artifact()` для этого не годился.

## Границы результата

Подтверждён только вывод о пригодности стенда. Ни один протокольный механизм от этого не изменился:
`E-0032` остаётся опровергнутой по своему порогу (3) как сформулирован, и ничего из `H-0032` этот
прогон не оживляет — он объясняет, почему одна из трёх точек молчала.

Случайные `i8`-центроиды — тоже не корпус: это равномерный шум в 384-мерной сетке, без кластерной
структуры реальных данных и без связи с записями. Их fan-out совпал с реальным корпусом, но почему
совпал — из этих чисел не следует (совпадение 14.35 против 14.3/14.4 — наводка на проверку, не
доказательство). Recall, как и в `E-0032`, не измерялся: гейт (ii) по-прежнему не закрыт.

Равномерная модель — расчёт, а не замер: она предполагает выбор `k` кластеров наугад из 1024, чего
никакое правило близости не делает, поэтому её числа (8,57 % и т. д.) сравниваются со снятыми, но
ничего не доказывают и в пороги не входили. Порог (2) был заявлен как «не меньше 11 из 256», снято
18; запас до фальсификатора (а) («ноль») здесь не проверялся на устойчивость к смене seed'а второго
стенда — это отдельное утверждение, пре-регистрации оно не имеет.

Workspace-проверка (`cargo test --workspace`, `cargo clippy --workspace --all-targets`) отложена до
конца `E-0027`: в этом цикле зелёным проверено всё `vecdht-artifact` плюс `clippy -p vecdht-artifact
--all-targets -- -D warnings`.
