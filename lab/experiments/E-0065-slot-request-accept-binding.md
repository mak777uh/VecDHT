# E-0065 — привязка `slot` запроса к предъявленному приёму (§12.4): расход проходит при любом `req.slot`, `NO_SUCH_SLOT` не конструируется нигде

## План прогона

Оракул `crates/vecdht-node/tests/slot_request_accept_binding.rs`, helper `lab/e0065-run.sh`
(структура секций как в зелёных `e0062`…`e0064`: BUILD `--no-run` → RUN `--nocapture` →
ИНВЕНТАРЬ → КОНТРОЛЬ `-p vecdht-node`; helper исполняет команду целиком — урок `e0049`).
Харнес одиночного primary: две публикации одного владельца (векторы 1 и 2) → `Find` вектором 1
при `now=0` → `MatchResult` с двумя слотами S0/S1 и живой приём F0 на S0; мутанты — пере-подпись
тела приёма ключом узла (метод `E-0064`, unchanged-база (0) закрепляет побайтовое равенство).
`serve_request` вызывается напрямую, `issuers = [n.me()]`; varying — только `req.slot` (S1,
0xFFFF_FFFF). Часы не двигаются (урок `E-0060`); живого текстового обслуживания нет — меряется
ровно гейт привязки. Пороги (0)…(6) и фальсификаторы (а)…(е) заморожены в `H-0065` до первого
замера; коммит пре-регистрации пушится до измерений. ИНВЕНТАРЬ фиксирует опоры: объявление
константы и все её упоминания (ожидаем — только объявление и два комментария), отсутствие
чтения `req.slot` в `session.rs`/`rendezvous.rs`, цитата §12.4.
