# E-0029 — читается ли поле `shard` там, где `E-0028` не нашёл валидатора

## Гипотеза

См. `H-0028`: поле `shard` у `MatchResult` и `RendezvousAccept` декодируется без проверки
диапазона, но, как утверждается, не читается ни одним путём обработки — то есть является мёртвым,
и стадия 1 не обязана его править.

## Стенд (правок нет)

Три grep-измерения плюс печать самих строк, чтобы классификация «чтение значения / отчёт /
производство кадра» была в логе, а не выводилась из числа. Отдельный нефильтрованный счётчик (1а)
по формам `res.shard|mr.shard|answer.shard|rdo.shard`; фильтры (1) служат только для сокращения
шума и на порог не влияют.

## Прогон

Одна попытка, `lab/logs/e0029-all.log`, 04:54+03:00, grep-only (сборки не было, цепочка `E-0027`
не затронута). Измерения:

- **(1)** чтения `.shard` вне тестов/комментариев по `net`/`node`/`index` — сводка в логе;
  нефильтрованный счётчик форм `res|mr|answer|rdo` + `.shard` = **2 строки**, обе
  `agent.rs:1225` (`if res.shard != shard`) и `agent.rs:1228` (та же проверка в тексте ошибки).
- **(2)** упоминаний `RendezvousAccept` вне тестов/комментариев = **29**; приёмник кадра —
  `agent::verify_standalone_accept` (`agent.rs:1041+`): decode → проверка подписи по байтам кадра
  (`verify_body`) → `check_accept_policy`. В политике читается `acc.seeker`, `acc.ttl_sec`
  и `acc.shard` (`agent.rs:932`: `acc.shard != shard || shard >= SHARDS`).
- **(3)** аргумент `shard` в двух вызовах `verify_match_result` — локальный (`entry.shard:787`,
  параметр `shard:1192`); подпись сверяется по байтам кадра (`frame`), а не по пересборке.
- **(4)** нормативного требования «отвергать вне диапазона на декоде» в спеке нет
  (`SHARDS` только в `:477` и в таблице `:1867`; подстрока «обязан…вне диапазона» — 0 совпадений),
  то есть расхождение «декод принимает» — не конфликт со спекой, а недо-валидация wire-слоя.

## Результат

Гипотеза **опровергнута** по порогу (1): поле `MatchResult.shard` читается агентом,
и читается в ветке управления (`verify_match_result`, `agent.rs:1225`), поэтому называть его
мёртвым нельзя. Но механизм чтения — сравнение с локальным значением (`res.shard != shard`
→ `BadAnswer`), а не доверие проводу: внедиапазонное число (`4095`) не проводится и не смещает
роутинг, а лишь даёт расхождение с локальным `entry.shard` и отказ. То же для
`RendezvousAccept`: приёмник есть (политика `check_accept_policy`), диапазоном он занят
(`agent.rs:932`), а не декодер.

Практический вывод для стадии 1 (он шире исходной формулировки `H-0028`): отсутствие
валидатора в wire-слое — не дыра допуска, а **ловушка ротации**. Когда `nlist` станет данными
артефакта, `SHARDS = nlist/16` перестанет быть константой; проверки `>= SHARDS` разбросаны
по трём слоям, и ротация обязана пройтись по всем, а не только по декодеру. Замеренная карта
(вне тестов и комментариев, с exact-строками в `e0029-all.log`):

- **wire-декод (class B на декоде):** `messages.rs:259` (`Publish.cluster_id`), `:664`
  (`LeaseGrant.shard`), `:728` (`SnapshotOffer.shard`), `:801` (`ReplicateAck.shard`),
  `cert.rs:92`; на `Find.clusters` и `Match.cluster_id` валидатора нет (`E-0028` 2-б/2-в),
  на `MatchResult.shard` и `RendezvousAccept.shard` — тоже нет (это и есть находка `E-0028` 2-а).
- **индекс (приём записи):** `ivf.rs:314` (`insert`), `ivf.rs:391` (`apply_op`), обе — `>= NLIST`;
  поиск защищён `.get()` (`ivf.rs:477`) и внедиапазонный кластер просто пустой.
- **агент/узел (политика):** `agent.rs:932`, `:1153`, `:1343` (`>= SHARDS`), `node.rs:466`, `:877`,
  `:1053` (сравнение с `self.shard`), `lease.rs:98`, `membership.rs:138`, плюс сверка манифеста
  `agent.rs:80-85` (класс A) и `NetworkParams::shard_of_cluster` (`agent.rs:128`, по runtime-
  `nlist` — единственный слой, уже готовый к параметру).

То есть правка стадии 1 — это 4 декод-сайта + 2 индексных + ~9 политических, и инвентарь `H-0027`
(97 сайтов) покрывал только байты и проверки значений, но не разделял «проверка на декоде»
и «сравнение в политике», — для ротации это разные по цене правки.

## Границы результата

- Измерено grep'ом по дереву `52289f1`, только нетестовый код; классификация «значение влияет на
  поток» делалась чтением соответствующих функций (строки приведены), а не только счётчиком.
- Про «нет дыры допуска» запись утверждает ровно одно: внедиапазонные значения этих двух полей
  приводят к отказу или к пустому результату, а не к приёму чужих данных. Это НЕ утверждение о
  безопасности протокола в целом — другие векторы (§14.4 «надувание кластеров») здесь не проверялись.
- Порог не смягчался: (1) не выполнен → вердикт `refutes`. Изменение формулировки в пользу
  гипотезы («читается, но безопасно») зафиксировано отдельным пунктом, а не как успех.
- Класс (H) из `H-0027` (молчаливые опоры на 64 шарда) остаётся непроверенным: сеть, `E-0030+`.
