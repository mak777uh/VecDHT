# H-0067 — разведка: грант будущей эпохи как заморозка шарда

Дата: 2026-10-22. Статус: разведка перед пре-регистрацией. Правки спеки и кода не производятся.

## Что уже покрыто и не перемеряется

* `lease.rs::tests` — `Stale` только для `g.epoch < have`, `Expired`, `ForeignShard`,
  `BadSignature`, `MissingSignature`; это юнит-уровень функции, не путь узла.
* `E-0066` — грант **прошлой** эпохи на живом смещённом primary: `P.tick(5)` → две
  `LeaseGrant` эпохи 1, обе реплики отвечают `EPOCH_STALE`; `serving_epoch` не меняется.
* `gates_p4.rs` — handoff после смерти primary, рестарт со старым epoch, W=2, снапшот seed.

Не покрыто: грант **будущей** эпохи (`g.epoch > have`) и привязка гранта к членству.

## Код: где именно дыра

`handle_lease_grant` (`node.rs:605-628`) делает три вещи:

1. `Lease::verify(bytes, shard, have, now)` — подпись, шард, `Stale` только при
   `g.epoch < have`, `Expired`;
2. проверяет, что `grant.primary_ed25519 == from == lease.primary` — то есть грант
   самосогласован по ключу, но **не** сверяет этот ключ с составом эпохи;
3. `self.lease = Some(lease)` — принимает без ответа и без `Error`.

`lease.rs:111-115`: `if let Some(have) = have_epoch { if g.epoch < have { Stale } }`.
Ветки «`g.epoch > have`» нет. Комментарий в `node.rs:614-616` обещает защиту от
«любой наблюдатель объявляет себя primary», но проверка `primary_ed25519 == from`
этого не даёт: наблюдатель подписывает грант своим ключом и объявляет primary себя.

Дальше срабатывает не сетевой, а локальный инвариант `lease_active`
(`node.rs:259-264`): lease действует только при `l.epoch == m.epoch()`. Узел остаётся
на эпохе 1, lease становится эпохи 1000 — `lease_active` ложен, `serving_epoch`
(`node.rs:270-275`) возвращает `None`, потому что первая же проверка не проходит.

## Почему это не «просто отказ одному узлу»

* `handle_publish` (`node.rs:676-686`) проверяет `is_primary` (членство не менялось — P
  по-прежнему primary), затем `serving_epoch` → `EPOCH_STALE` **до** admission, PoW и
  WAL. В отличие от E-0066, локальной записи не будет вовсе.
* `tick` (`node.rs:297-318`) входит в ветку продления только при `lease_active`;
  при ложном lease не будет ни `LeaseGrant`, ни `TimeMark`, ни GC.
* `should_propose` (`node.rs:332-365`) при неизменном составе берёт
  `base = lease.expires_at_bucket` — то есть **чужой** срок. Пока `now < base + rank *
  election_buckets`, узел не предлагает следующую эпоху. Своя настоящая lease истекла
  на бакете 6, но base — атакующий.
* Если грант доставлен всем членам, каждый из них теряет и запись, и право голоса:
  шард не может ни принять publish, ни выбрать новый состав, хотя все узлы живы и
  состав полон.

## Срок и границы атаки

* `expires_at_bucket` выбирает атакующий. `u32::MAX` — практически «до рестарта»:
  `active_at` и `should_propose` не дойдут до этой границы.
* Атака требует доставить по одному кадру каждому члену (или всем говорящим). Это
  дешевле любой Sybil-атаки: подпись гранта — единственная криптография, членство и
  PoW не нужны.
* Транспорт в замере — прямой `on_frame`; handshake §5.3 и NodeCert не меряются. В
  реальной сети доставить кадр должен тот, кого транспорт аутентифицировал; это может
  быть любой держатель кредашиала, агентский порт или скомпрометированный узел.
* Рестарт, вероятно, снимает заморозку (lease живёт в RAM и не персистится), но это
  отдельный вопрос и в этом цикле не меряется.
* Тот же `handle_lease_grant` принимает и грант **текущей** эпохи от произвольного
  ключа (`g.epoch == have`, `expires > now`). Он не блокирует запись сразу, потому что
  `lease_active` смотрит только на epoch, но подменяет `lease.primary`. Это соседняя
  грань той же отсутствующей проверки членства; в пороги не входит.

## Что мерить (черновик до заморозки)

1. База: P эпохи 1 пишет A, W=2 даёт `PublishAck{OK}`, `applied_seq=1` у всех.
2. Грант `epoch=1000, expires=u32::MAX` от не-члена, доставленный всем трём: пустой
   ответ, epoch остаётся 1, `lease_active=false`, `serving_epoch=None`.
3. Publish B на P: ровно `EPOCH_STALE`, ни `ReplicateOp`, ни WAL, `applied_seq` не растёт.
4. `tick(6)` (настоящая lease истекла) и `tick(1000)`: пусто у всех — ни продления, ни
   предложения эпохи 2.
5. Второй трио с `expires=10`: `tick(9)` пусто, `tick(10)` у говорящего ранга 0 —
   первые `MembershipUpdate` эпохи 2. Срок заморозки равен чужому `expires`, а не 6.

## Кандидат на ADR после замера

Проверка `g.epoch < have` — это только половина fence. Варианты лечения (не выбирать до
измерения):

* (a) принимать грант только при `g.epoch == have`; прошлый primary перестаёт
  демотироваться грантом и остаётся harmless-писателем (E-0066), но пропадает обещанная
  §9.8 само-демоция «увидев lease с большим epoch»;
* (b) грант будущей эпохи обязан нести доказательство членства (подписи порога или
  `MembershipUpdate`), иначе `EPOCH_STALE`;
* (c) сверять `g.primary_ed25519` с primary эпохи `g.epoch` по детерминированному
  кандидатскому порядку; ломается на разделении, где живой ростер старого primary
  содержит его самого (E-0066, `MembersOutOfOrder`).

Выбор требует замера и отдельного ADR; в этом цикле только измерение.
