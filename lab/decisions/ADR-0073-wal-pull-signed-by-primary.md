# ADR-0073: хвост WAL — подписанный ответ primary, а не доверие пиру

## Контекст

`WalPullResponse` — единственный кадр, который несёт `ReplicateOp`-поток не по одному, а пачкой
durable-фреймов. Формат `wal.rs` не содержит ни эпохи, ни подписи: `crc32 ‖ seq ‖ kind ‖ len ‖ body`.
Подпись кадра `ReplicateOp` остаётся на проводе и в WAL не кладётся. Пока ответ был неподписан,
догоняющий верил любому пиру, совпавшему по шарду: эпоха из тела подставлялась в каждый оп, а
`seq` брался из фреймов. `apply_replicated` отсекает только `epoch < max_epoch_served`, поэтому
ответ с большей эпохой и произвольными `seq` менял индекс реплики.

## Решение

1. `Kind::WalPullResponse` — обязательная подпись (`frame.rs::signature_required`); кадр без
   подписи отбрасывает дверь `on_frame` до обработчика.
2. `handle_pull_request` подписывает `body_bytes()` ключом узла доменом `domain::WAL` и отдаёт
   `encode_signed`. Узел без эпохи (`primary_epoch == 0`) хвост не отдаёт.
3. `handle_pull_response` до чтения фреймов проверяет: непустой `primary_epoch`; при
   `self.epoch() == Some(e)` — `primary_epoch == e` и `from == membership.primary()`; при
   `self.epoch() == None` — `from` из `roster`; `from_seq <= applied_seq + 1`; подпись
   `verify_body(&from, domain::WAL, Kind::WalPullResponse, frame.body, sig)`.
4. После `install_snapshot` следующий `pull_request` адресуется primary принятой эпохи; без
   членства — отправителю снапшота.
5. Спека приведена к факту в пяти местах (§4.3, §5.3, §9.4 ×2, §9.7, §9.8): durable-фрейм не несёт
   эпохи и подписи, ответ несёт `primary_epoch` и подпись primary, дверь проверяет автора.

## Почему не `owner == from` и не серверный гейт

`owner == from` для `Publish` (T1) несовместим с gossip: узел получает `from` пересылающего
транспорта, а не автора тела. Здесь та же логика: `from` — это транспортный пир, и подпись
проверяется именно по нему. Серверный гейт «primary только» не нужен: тёплый получатель сам
отвергает не-primary, а холодный узел без членства должен иметь право добрать хвост у seed'а.

## Последствия

* Тёплая реплика, ответившая на pull, получает молчание вместо применения — это намеренно.
* Подпись ответа не атрибутирует отдельный `InsertOp`; это названная граница, а не забытая дыра.
* Тело ответа не меняется, golden-векторы не двигаются; меняется только матрица подписей и
  трейлер кадра.
* Любой пре-релизный узел, не подписывающий `WalPullResponse`, перестаёт отдавать хвост; версия
  не тегирована, поэтому это записано в CHANGELOG как пре-релизный слом.
